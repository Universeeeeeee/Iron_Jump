# 八米 LED 状态采集软件接口与操作说明

## 1. 软件用途

本软件通过 USB 采集八段 LED 阵列的状态，并实时显示 1m 至 8m 共八个面板。每段包含 96 个 LED，共 768 个状态位。软件由三米版（led_con_package_3m）移植而来。

主要功能：

- 自动连接指定 VID/PID 的 USB 设备并控制采集启停；
- 检查帧头、数据长度、CRC8 和帧尾，处理 USB 粘包与拆包；
- 按可配置的物理线序（`DAYU_SEGMENT_ORDER`）将数据归一化为 1m 至 8m；
- 排除长度异常、整帧全灭、分包不完整、位置异常和短时抖动帧；
- 采集时自动保存原始 USB 数据 CSV 和软件状态日志；
- 结束测试后可将有效 LED 状态导出为 Excel。

## 2. 运行环境

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10/11 64 位 |
| Python | 64 位 Python 3.11 或 3.12 |
| USB 驱动 | 已安装采集设备对应的 Windows 驱动 |
| USB 动态库 | 默认 `hardware\CyUsbInterface.dll` |
| 默认 VID | `0x04B4` |
| 默认 PID | `0x1004` |

首次运行需要联网安装 Python、Qt 和 Excel 依赖。安装完成后，后续启动通常不再需要联网。

## 3. 启动软件

1. 将软件包完整解压到本地磁盘，不要直接在压缩包预览窗口中运行。
2. 连接 USB 采集设备，确认 Windows 驱动正常。
3. 双击项目根目录中的 `start_led_con.bat`。
4. 首次启动会自动创建 `.venv` 并安装依赖，请等待安装完成。
5. 软件窗口打开后，点击“开始测试”。

也可以在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe ui\led_con_8m.py
```

## 4. 界面说明

界面左侧显示最近收到的有效数据；右侧为 2 列 × 4 行网格，依次是 1m 至 8m LED 面板。每个面板为 8 行 × 12 列，共 96 个 LED。

- 绿色：LED 亮或光路未遮挡；
- 灰色：LED 灭或光路被遮挡。

界面以约 60 FPS 读取最新有效状态。接收速度高于显示速度时，旧显示帧会被新帧覆盖，避免长期积压；完整原始数据仍由后台线程记录。

## 5. 操作流程

### 5.1 开始测试

1. 确认设备已连接。
2. 点击“开始测试”。
3. 软件自动创建日志、加载 DLL、打开设备、启动读取线程并向 FPGA 发送采集使能命令。
4. 确认八个面板与左侧数据持续更新。

### 5.2 暂停与继续

- 点击“暂停”后，界面停止刷新。
- 暂停期间 USB 接收、异常帧判断、原始 CSV 和有效帧归档仍继续。
- 点击“继续”后直接显示当前最新状态，不会回放暂停期间的旧画面。

### 5.3 结束测试

1. 点击“结束”。
2. 软件发送停止命令，停止 USB 读取，并等待后台日志写入完成。
3. 软件询问是否保存有效状态 Excel：选择“是”则保存，选择“否”则不生成 Excel。
4. 原始 CSV 和状态日志不受 Excel 选择影响，采集开始后即自动保存。

如需保存 Excel，请通过“结束”按钮结束。直接关闭窗口会停止接收并关闭日志，但不会弹出 Excel 导出询问。

## 6. 数据文件

### 6.1 原始 USB 数据 CSV

保存目录：

```text
data\capture_logs
```

文件名：

```text
raw_YYYYMMDD_HHMMSS_mmm_part001.csv
```

单个 CSV 默认最大约 256 MB，达到限制后自动生成 `part002`、`part003`。软件不会自动删除历史日志，长期采集前应确认磁盘空间。

| 字段 | 含义 |
| --- | --- |
| `wall_time` | 本地接收日期和时间，精确到毫秒 |
| `monotonic_ns` | 单调时钟纳秒值，可用于计算接收间隔 |
| `byte_count` | 本次 USB 读取返回的字节数 |
| `raw_hex` | 本次读取的全部原始字节，十六进制表示 |

CSV 一行对应一次 USB 读取，不一定对应一个协议帧。一个帧可能跨越多行，一行也可能包含多个帧，帧边界必须按第 8 节协议判断。

### 6.2 软件状态日志

状态日志位于同一目录，文件名为：

```text
status_YYYYMMDD_HHMMSS_mmm.log
```

日志记录设备连接、采集启停、暂停与继续、异常计数和约每秒一次的心跳。

| 字段或事件 | 含义 |
| --- | --- |
| `logger_started` / `logger_stopped` | 后台日志线程启动或结束 |
| `capture_starting` / `capture_stopping` | 采集开始或停止 |
| `device_state` | 连接中、已连接、采集中、错误或断开 |
| `ui_paused` / `ui_resumed` | 界面暂停或继续 |
| `heartbeat` | 周期运行状态 |
| `raw_chunks` / `raw_bytes` | 已写入的数据块数和字节数 |
| `accepted_frames` | 已归档的有效 LED 帧数 |
| `rejected_payloads` | 长度错误或整帧全灭的数据数 |
| `rejected_alignment_frames` | 未通过坏灯位置校验的帧数 |
| `raw_queue_depth` / `frame_queue_depth` | 后台写入队列积压数量 |
| `dropped_raw_records` / `dropped_frame_records` | 为避免阻塞接收而放弃的记录数，正常应为 0 |

排查长时间卡顿时，请同时提供同次采集的 `status_*.log` 和全部 `raw_*_partNNN.csv`。

### 6.3 有效状态 Excel

点击“结束”并确认保存后，在 `data` 目录生成：

```text
led_frames_8m_YYYYMMDD_HHMMSS.xlsx
```

Excel 共 769 列：第 1 列是采集开始后的时间；随后依次是 96 列 1m、96 列 2m、……、96 列 8m 状态。Excel 只包含通过所有检查的有效帧，原始 CSV 保存过滤前的 USB 数据。

## 7. 八段数据映射

设备发送的 96 字节 LED 数据按 12 字节一组共 8 组排列。组与物理米段的对应关系由环境变量 `DAYU_SEGMENT_ORDER` 决定，默认为现场确认的线序（沿用 3m 版 [2m, 3m, 1m] 的规律：自 2m 起顺序递增，1m 为最后一组）：

| 原始字节范围 | 默认物理段 |
| --- | --- |
| 0～11 | 1m |
| 12～23 | 2m |
| 24～35 | 3m |
| 36～47 | 4m |
| 48～59 | 5m |
| 60～71 | 6m |
| 72～83 | 7m |
| 84～95 | 8m |

`DAYU_SEGMENT_ORDER` 为逗号分隔的 8 个数（1..8 的排列），第 i 个数表示线上第 i 组（0 起，即字节 12i～12i+11）对应的米段编号。默认值为 `1,2,3,4,5,6,7,8`（现场实测恒等线序）。例如实际线序为 [2m, 3m, 1m, 4m, 5m, 6m, 7m, 8m] 时应设置为 `2,3,1,4,5,6,7,8`。

软件归一化后，界面、有效数据和 Excel 均按 1m 至 8m 顺序输出。每个字节按最低位到最高位展开为 LED 状态。

## 8. USB 数据接口

### 8.1 设备报告帧

| 顺序 | 字段 | 长度 | 说明 |
| --- | --- | --- | --- |
| 1 | 帧头 | 4 字节 | `5A 5A 5A 5A` |
| 2 | 类型 | 1 字节 | ACK=`80`，状态=`81`，数据=`82` |
| 3 | 数据长度 | 2 字节 | 小端序，仅表示 payload 长度 |
| 4 | payload | N 字节 | 按类型解释 |
| 5 | CRC8 | 1 字节 | 对“类型 + 长度 + payload”计算 |
| 6 | 帧尾 | 4 字节 | `A5 A5 A5 A5` |

CRC8 使用多项式 `0x07`、初始值 `0x00`、不反射、异或输出 `0x00`。

数据报告 `0x82` 的 payload：

| 字段 | 长度 | 说明 |
| --- | --- | --- |
| `frameIdx` | 4 字节 | 大端序无符号帧号 |
| `packNum` | 1 字节 | 分包总数 |
| `packIdx` | 1 字节 | 当前分包编号 |
| LED 数据 | 12 或 96 字节 | 状态数据 |

八米数据支持两种形式：

| 形式 | `packNum` | 每包 LED 数据 | 完整协议包长度 |
| --- | ---: | ---: | ---: |
| 单包 | 1 | 96 字节 | 114 字节 |
| 八分包 | 8 | 每包恰好 12 字节 | 每包 30 字节 |

八分包编号允许从 0 或 1 开始。软件在一次采集中确认编号基准后保持固定。每包必须恰好 12 字节，避免总长为 96 但边界错位。

### 8.2 采集控制命令

```text
5A 5A 5A 5A | CMD | LEN | PARA | CRC8 | A5 A5 A5 A5
```

| 操作 | `CMD` | `LEN` | `PARA` |
| --- | --- | --- | --- |
| 开始采集 | `00` | `10` | `01` |
| 停止采集 | `00` | `10` | `00` |

`LEN=10` 的高 4 位表示参数长度为 1 字节。CRC8 对 `CMD + LEN + PARA` 计算。

### 8.3 1 ms 数据周期

设备采样周期为 1 ms，但 Windows 不保证每 1 ms 返回一次 USB 数据。软件按连续字节流处理：保留跨读取的半帧、逐帧解析粘包、按协议长度定位帧尾；坏包逐字节重新寻找帧头，不按时间强行切割帧。

## 9. 异常帧判断

以下数据不更新面板，也不进入有效状态 Excel：

- 帧头、类型、长度、CRC8 或精确位置帧尾错误；
- 八米 LED 数据不是完整 96 字节；
- 八分包中任一包不是 12 字节；
- 分包数量、编号或同编号内容冲突；
- 不完整分包超过 1 秒；
- 完整 96 字节全部为 `00`，即整帧 768 位全灭；
- 未通过坏灯位置校验（`DAYU_REQUIRED_DARK_BITS` 指定的位被点亮）；
- 新状态未达到稳定确认条件。

单段全灭和局部遮挡不会仅因状态为灭而被过滤。

默认稳定确认要求新状态连续至少 3 帧相同，并从首次出现起持续至少 10 ms。恢复到上一稳定状态可立即通过。该机制会排除短暂跳变，也可能忽略不足 10 ms 的真实短遮挡。

3m 版默认启用的“2m 首灯永久损坏”校验是旧套件特有的硬件缺陷检查，8m 版默认不启用。现场确认固定坏灯后，设置 `DAYU_REQUIRED_DARK_BITS`（线序位索引 0..767，逗号分隔）启用同类位置校验。

## 10. 环境变量接口

变量需要在启动前设置，修改后重启软件生效。

| 变量 | 默认值 | 用途 |
| --- | --- | --- |
| `DAYU_DLL` | 自动查找 | DLL 完整路径 |
| `DAYU_VID` | `0x04B4` | USB Vendor ID |
| `DAYU_PID` | `0x1004` | USB Product ID |
| `DAYU_TIMEOUT` | `1` | USB 超时，单位 ms |
| `DAYU_CHUNK` | `2048` | 单次最大读取字节数 |
| `DAYU_SEGMENT_ORDER` | `1,2,3,4,5,6,7,8` | 物理线序：第 i 组对应的米段编号（1..8 的排列） |
| `DAYU_REQUIRED_DARK_BITS` | 未设置 | 必须保持熄灭的线序位索引（0..767，逗号分隔），空为不校验 |
| `DAYU_FRAME_CONFIRM_MS` | `10` | 新状态确认时间；`0` 关闭时间确认 |
| `DAYU_RAW_CSV_MAX_MB` | `256` | 单个原始 CSV 最大容量，单位 MB |
| `DAYU_LOG_INTERVAL_MS` | `100` | 左侧文本更新最小间隔，单位 ms |
| `DAYU_TARGET_RATE_HZ` | `200` | LED 信号目标更新频率 |
| `DAYU_LED_INTERVAL_MS` | 未设置 | 直接指定 LED 信号间隔 |
| `DAYU_DEBUG_USB_RAW` | `0` | `1` 时在界面显示原始读取摘要 |

设置示例：

```bat
set DAYU_RAW_CSV_MAX_MB=512
set DAYU_SEGMENT_ORDER=2,3,1,4,5,6,7,8
call start_led_con.bat
```

## 11. 常见故障

### 找不到 Python

安装 python.org 提供的 64 位 Python 3.11 或 3.12，安装时启用“Add Python to PATH”和 Python Launcher。

### DLL 加载失败

检查 DLL 是否存在，Windows、Python、DLL 是否均为 64 位，并确认已安装设备驱动和 Microsoft Visual C++ 运行库。DLL 位于其他目录时设置 `DAYU_DLL`。

### 设备无法连接

检查 USB 线、电源、设备管理器驱动和 VID/PID；关闭可能占用同一设备的其他程序，重新插拔后再启动。

### 面板长期无变化

1. 在 `status_*.log` 中检查 `device_state`。
2. 检查连续心跳：
   - `raw_bytes` 不增长：设备或 USB 读取未继续产生数据；
   - `raw_bytes` 增长、`accepted_frames` 不增长：数据未通过协议或异常帧检查；
   - 两项 `dropped_*` 大于 0：后台写入速度不足或磁盘异常。
3. 使用同次原始 CSV 检查帧头、长度、CRC8 和帧尾。

### 面板数据与米段不对应

确认 `DAYU_SEGMENT_ORDER` 与实际线序一致。默认值 `1,2,3,4,5,6,7,8` 为现场实测的恒等线序；如实际布线不同，请先以已知的遮挡图案确认各面板归属再调整。

### 显示卡顿

检查磁盘空间以及状态日志中的队列深度和丢弃数，也要检查杀毒软件是否持续扫描增长中的 CSV。暂停后继续只影响显示；需要重新初始化设备时，点击“结束”后重新开始。

### Excel 没有生成

必须点击“结束”并选择“是”。如果没有有效帧，软件不会询问导出。原始 CSV 和状态日志不依赖 Excel 确认。

## 12. 提交问题所需资料

请提供：

1. 问题发生时间和具体操作步骤；
2. 同次采集的 `status_*.log`；
3. 同次采集的全部 `raw_*_partNNN.csv`；
4. 对应的 `led_frames_8m_*.xlsx`（如有）；
5. 设备 VID/PID，是否更换过 USB 端口或线缆；
6. 当时的 `DAYU_SEGMENT_ORDER` 设置；
7. 异常表现，例如段数据平移、全灭、频闪或停止更新。

状态日志和原始 CSV 含设备通信及 LED 位数据。对外提供前，请按现场数据管理要求处理。

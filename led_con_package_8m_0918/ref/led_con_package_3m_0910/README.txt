96-LED 状态可视化程序（Windows 64 位）
======================================

完整的软件接口、操作流程、日志字段和故障排查说明见：
软件接口与操作说明.md

运行条件
--------
1. Windows 10/11 64 位。
2. 已安装 64 位 Python 3.11 或 3.12，并在安装 Python 时勾选
   “Add Python to PATH”。
3. 已安装采集设备对应的 Windows USB 驱动。
4. 首次运行需要联网下载约数百 MB 的 Python/Qt 依赖。

使用方法
--------
1. 将 ZIP 完整解压，不能直接在压缩包预览窗口中运行。
2. 双击 start_led_con.bat。
3. 首次运行会在当前目录创建 .venv 并自动安装依赖，请等待完成。
4. 程序窗口打开后连接设备，点击“开始测试”。

默认硬件参数
------------
VID: 0x04B4
PID: 0x1004
DLL: hardware\CyUsbInterface.dll（64 位）

如果设备参数不同，可以在启动前设置以下环境变量：
DAYU_VID、DAYU_PID、DAYU_DLL、DAYU_TIMEOUT、DAYU_CHUNK。

界面说明
--------
右侧为 8×12、共 96 个 LED 状态：绿色表示 LED 亮/未遮挡，灰色表示
LED 灭/遮挡。结束测试时可选择将采集数据保存为 Excel；文件位于包内
data 目录。

故障排查
--------
- 提示 Python was not found：安装 python.org 提供的 64 位 Python。
- Python 已安装但 py 命令不存在：重新安装并启用 Python Launcher 和 PATH。
- DLL 加载失败：确认系统和 Python 均为 64 位，并安装设备驱动及 DLL 所需
  的 Microsoft Visual C++ 运行库。
- 设备无法连接：检查驱动、USB 连接以及 VID/PID 是否与设备一致。


三米版映射与异常帧过滤（2026-09-07）
------------------------------------
三米版将收到的三组12字节依次解释为2m、3m、1m，面板、日志及
Excel统一按1m、2m、3m输出。修改后须关闭旧窗口并重新启动。
仅完整36字节的有效帧更新界面；长度不符、分包编号/数量异常、
冲突重复分包、整帧36字节全部为0（288灯全灭）的数据不显示、不导出。
异常帧不会清空上一帧；单段全灭和局部遮挡保留。CRC或帧尾校验
失败的数据仍由协议层丢弃。不完整分包超过1秒后不再参与拼接。

频闪过滤（基于无遮挡样本 led_frames_3m_20260907_154941.xlsx）
------------------------------------------------------------
默认启用状态确认：新状态连续至少3帧相同，并从首次出现起持续至少
10毫秒，才用于显示、日志和导出。确认前保留上一有效帧；恢复到
上一有效状态可立即通过。不会补造或强制点亮任何LED，2m固定坏灯
保持原样。稳定的局部遮挡、单段全灭同样可在确认后通过。
可用 DAYU_FRAME_CONFIRM_MS 调整毫秒阈值，设为0关闭时间确认
（长度、分包和整帧全灭过滤仍生效）。程序重启后生效。
注意：这是时间去抖，会剔除不足确认条件的真实短遮挡；持续变化、
始终不能稳定的状态也会被暂缓，不能直接用于要求保留每次短脉冲的
精确计时。该Excel是界面抽样导出，回放不能替代原始USB及实机验证。

米段位置校验
------------
三米界面默认按已确认的2m首灯永久损坏进行位置校验：线序第一组
首字节bit0必须为0（当前LSB表示为FE，反位序为7F）。不满足的帧
在稳定确认之前丢弃，不更新面板、不进入导出，也不自动旋转数据。
3个分包的三米帧还要求每包恰好12字节，避免总长虽为36但边界错位。
更换或修复该坏灯后，设置 DAYU_CHECK_2M_FIRST_LED=0 关闭此硬件
特定校验，重启程序生效。
位置校验是基于已知坏灯的异常拦截，不是协议级段ID。如果错位后
其他段恰好在同一位被遮挡，仅凭位图无法保证识别；上游每段携带
固定节点ID才可无歧义恢复段身份。现有资料无法确认上游错位来源。

1ms数据周期接收与边界校验
------------------------
三米界面默认USB超时改为1ms（DAYU_TIMEOUT可覆盖），采集命令也
保持相同超时，避免发送命令把读取超时重置为1000ms。
每个协议包按5A5A5A5A帧头、合法类型/长度、精确偏移的A5A5A5A
帧尾和CRC8校验。36字节单包数据加6字节元信息时，完整包为54字节；
三分包模式每包12字节数据时完整包为30字节。坏包逐字节重新找头，
不会按损坏长度把下一包一起删除；跨USB读取的半帧继续缓存。
完整帧按近期(帧号、内容)去重，窗口最多64帧且最多100ms；不再假定
计数器必须32位递增，短位宽回绕、前向跳号不会永久屏蔽后续数据。
1ms是设备采样周期，不是Windows回调到达间隔。接收线程逐帧解析
粘包，不按墙钟1ms硬切字节、不因短暂调度延迟丢半帧。该改动不把
现有约30Hz界面刷新和抽样导出变为1000Hz；原有10ms稳定确认保留。

长期采集修正（2026-09-08）
--------------------------
每个协议包继续检查帧头、长度、帧尾、CRC；每个完整帧继续通过长度、
坏灯位置和稳定性校验。帧号仅用于有限窗口去重及分包归属，不设置
永久的最大帧号门槛。窗口以外的旧帧不能只凭帧号可靠识别。
同一次采集确定分包从0或1开始编号后保持固定，不逐帧重新推断。
接收线程与定时刷新通过锁串行交换待显示数据，避免重复取出或覆盖。
导出记录最多占用256KiB内存缓存，超出部分写入系统临时文件，保存
Excel时逐批读取；关闭窗口删除临时缓存。长期采集需要可用磁盘空间。
这些测试修复了可复现的接收端状态问题，不代表已经完成现场长时间
硬件验证，也不能仅凭位图保证识别所有传输中的段身份异常。

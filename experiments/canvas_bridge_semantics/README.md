# AnnotationCanvas 调用桥的有限语义验证

基于 d9fdbe9，暂停扩展进程隔离，服务于相机预览绘制 GIL 边界的最小因果实验。正式程序、原 NumPy、滤波、Processor、原绘图候选和线程结构未改。没有人体、USB、Run 或性能 A/B。

通过独立子类替换 AnnotationCanvas.paintEvent 的第一条 QLabel 基类调用。AST 门禁确认其余绘制语句不变，原类方法始终未修改。实验桥沿用已核验的同步调用上下文、异常检查与对象强引用，仅在原生基类调用边界释放/重新获取 GIL；这仍是固定二进制 ABI 的实验工具，不是正式修复。

实际 Windows 交互后端、784×441 逻辑尺寸、DPR 1.25、位图 DPR 1 下，8 组完整像素逐字节一致：空图、普通图像、骨架、低质量骨架、镜像、角度拖拽及草稿、时间区间、组合覆盖。观察到低质量骨架与无骨架图像相同，有效骨架及镜像确实改变图像。完整像素共16份，逐份2163840字节，由 review.py 从归档重新读取，不依赖保存的相等布尔值。

状态、坐标映射、绘制信号、GUI线程及事件生命周期检查一致。两种调用方式注入相同覆盖层异常，均在 render 调用处捕获原异常实例；取消注入后的完整恢复图像与原骨架图像一致，恢复图像也保留并独立复核。对象和事件过滤器删除确认。Win32/.NET 均确认进程退出码0，无目标遗留，四个锁保留，仅移除已结束的实验任务。

首次离屏控件窗口保留为失败：Qt报告默认字体目录不存在。随后字体专用预检分别暴露全字体目录 FreeType 解析诊断、精简字体夹具断言失败，以及SSH Windows后端启动DPI诊断；未忽略这些诊断追认通过，也没有再次启动同一失败计划。字体专用进程不执行控件比较或性能测试。最终另冻 plan02，使用与原GUI一致的交互式 Windows 后端和系统字体，验证字形索引、非空轮廓、不同中文字的实际像素；同控件进程内也再验证字体，未记录绘制诊断。系统字体目录和全局DPI配置未修改；实验复制字体仅留Windows独立目录/忽略归档，不推送字体文件。所有准备脚本、失败、原计划及结果保留。

plan01 的原窗口始终 passed=false；plan02 的有限语义门禁通过不替代它。旧CPU/CSwitch、实际负载3%/1%失败不变，不计算GIL/CPU贡献。进程隔离架构不扩展。

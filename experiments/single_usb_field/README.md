# 正式单 USB 有人现场复现阶段

基于 `210d86a` 的独立分支 `codex/single-usb-field-reproduction`。仅新增本实验目录，保留正式 NumPy、原绘图器及既有绘图候选；不改正式 hardware/、engine/、滤波、Processor 或阈值。

正式 Windows 根目录：`E:/OptoJump/IronJump-single-usb-field-20261016`。与旧空场、双输入和绘图实验目录隔离。原始 MJPEG 体积较大，保留于 Windows；取回测量、CSV、光束档案及报告，最终另记录录像哈希与大小。

## 现场操作

1. 先走路，后跑步，各一轮单次去程。站在光栅外，调整相机使头至脚完整入镜。
2. 等待原设备预检通过、SDK 启动、原始录像实际写入、全身关键点及真实下肢节点/连线连续有效。现场再目视核验并勾选确认框。
3. 点击窗口顶部开始；保持约 5 秒光栅空场，提示后单次通过，从跑道外离开。
4. 助手点击“人已离开”，继续 15 秒空场。若未点击，则上限 60 秒自动请求正式手动停止。
5. 等待原有停止/完整报告、录像落盘及 SDK 关闭完成后，才准备下一模式。

使用正式支持的 `stop_type='Software command'`，使通过后可继续收集排空段；其他走跑参数沿用默认值。窗口原“结束”仍可用于提前停止，但短尾段不会被当作满足现场协议。任何提前算法结束、数据断裂、准备条件或尾段不满足均单列，不当作性能通过。

## 观测与边界

- 正式唯一真实输入 `UsbWorker → _GroundFrameInbox → DeviceQualitySession → GaitEngine`；没有固定回放、第二路 USB 或候选绘图器。
- QueueProbe P 与上一轮逐字节相同。原消费包装每批保留原 items 列表的一个引用，停止后才序列化完整 SensorFrame 接触位/有效位/wire、设备/帧计数、接收时钟、丢帧、布局和质量标志/issue 顺序。没有新增逐帧 USB 信号接收者或逐帧 Python 计时器。
- 复用实际预览/骨架绘制函数，计数有效节点与连线；GUI 每秒控制/累计计数一次，SDK 原有事件在内存留存。仅记录首次确认脚印绘制完成，不嵌套计算处理器耗时。
- 原始录像使用正式 native MJPEG+CSV 和 `preserve_raw=True`；启动 API 前/后保留时钟区间。录像写入中被独占，不能仅凭路径存在宣称画面完整；采集停止后仍须核对 CSV 帧数/偏移/字节和原始画面。
- 全身关键点与持续绘制是实验开始门槛，不改变正式算法质量阈值。正式叠加层绘制下肢，SDK 使用全身跟踪；完整入镜还需要现场目视与录像核对。准备门槛通过不代表全程跟踪持续有效，必须看正式计数/SDK/录像。
- 新增批次引用留存、SDK 事件保存和控制计数仍有开销，未独立校准；较长准备时间还会增加保留内存。若复现，必须在解释原生调度前独立校准，不能将观测器压力当作正式程序根因。
- 队列最老年龄来自组帧后的应用接收时钟，不能证明原生线缆均匀到达；SDK/native CSV/设备计数并非已同步的同一时钟。

`plan.json` / `frozen_sources.json` 在各运行版本启动前冻结；`analyze.py` 在最初准备后新增，revision 2 的冻结清单包含其当时版本，它仅离线运行。准备截图尝试在正式开始前独立运行，不计入吞吐测量；不将截图失败视作 USB/相机采集失败。

## 决策

分别报告 5 秒初始空场、接触跨度、逐设备秒密度、离开后的空场、整轮队列/吞吐及实际绘制量。冻结门槛见 `plan.json`：持续队列增长并且入队近 1000 Hz、消费不足时，才进入独立 ETW/WPR 校准。没有复现则继续检查真实负载差异，不宣称修复。单轮异常还不能叫稳定复现。

原有末步漏发布与有效步间隔计数问题单独保存事件/报告，不修改或归一化；脚印延迟只覆盖确实发表并被绘制的事件，不包含漏发布事件，更不是计步正确性验收。

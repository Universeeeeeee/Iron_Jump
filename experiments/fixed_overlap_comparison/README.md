# 固定原工作单独／并发对照：达到预先冻结的方向性判据

本阶段按最新参考对话要求，直接用既有真实工作基准选择机制方向，没有继续扩展通用观测工具。4对、8个新进程全部完成；顺序固定为并发/串行、串行/并发、串行/并发、并发/串行，没有额外试次、筛选或替换。

## 单一改变与完整交付

两组均执行原始6,824帧消费工作和220次真实模型调用，模型同样先open并ready，图像、逻辑时间、原函数和完整返回身份相同。并发组在消费者开始时释放模型工作；串行组在消费者完成后释放。原模型线程仍存在，只改变实验中的工作重叠。

两组共同保存7个消费进度点（1000、2000、3000、4000、5000、6000、6824帧）。没有ETW、栈采样器、线程枚举或入口查询，没有预热策略、OpenCV线程数、GC、NumPy、滤波、Processor或绘图改动。

每窗均验证实际时间区间确实满足指定重叠关系，而非仅检查模式标志；完整原始报告、质量状态、原始帧保存、图像像素哈希和220次模型返回摘要均与原基准一致。模型关闭及原进程计数边界通过。

消费墙钟几何平均下降 **25.374%**，4对均改善，通过预先冻结的“所有配对改善且几何平均至少20%”方向性判据。唯一主要终点的配对log比值Student-t描述区间对应下降约 **19.945%–30.434%**；不能声称最低收益以95%置信度超过20%。小样本区间依赖独立性/近似正态假设，不是对所有运行状态的分布无关保证。

4对×7个消费分段，**28个分段的串行墙钟都更短**，差异不是只集中在一次启动停顿。消费线程CPU也在每对同向减少，分别为1125、578.125、656.25、765.625ms；不把墙钟与CPU差值命名为GIL等待份额，也不以进程CPU计算等待。

串行组整组工作完成时间反而比并发组增加约 **1.454–2.154秒**。因此，这个串行条件用于机制判断，正式候选仍应保留并发和视觉更新能力。

## 这一步改变了什么判断

**支持：** 在这个完整工作一致的固定协议中，模型流水线并发是消费者变慢的一个贡献因素，值得针对并发资源成本采取最小干预。墙钟和消费CPU均同向改变，削弱“这一效应完全由消费者阻塞等待造成”的简单解释，但尚未区分缓存、CPU交付、实际执行成本与同步的具体贡献。

**仍未知：** 第一对的并发和串行都比后续同组窗口慢；串行自身从3811ms降到约2114–2270ms，说明还有不能仅由本次模型重叠变量解释的运行状态波动。全部首对数据保留，没有用快态子集代替整体结果。

这不是GUI积压修复验收。没有实时1000Hz输入、pending、contact→paint或真实SDK指标；固定模型工作连续运行，不能把25.4%直接当作现场根因占比或预期现场收益。旧3%/1%及原生栈验收失败保持。

# 原生边界与空白控制：针对Python包装成本的独立协议

承接f6bacea：Python边界协议活跃指令量与线程CPU门通过，但空白约1.16–1.28%超过1%，整体失败保留。本协议只移除测量块内的Python包装，不扩大工作量稀释开销，也不扣空白、放宽门槛或替换旧窗口。

Rust无外部crate，直接调用Win32 Sleep/QPC/GetThreadTimes/QueryThreadCycleTime和固定72字节RX代码。机器码、1/2/17正控制、8个块及原来的顺序、Sleep10ms、指令比例[.97,1.03]、空白1%、OS记账31.25ms门均相同。新增3项原生测试验证固定代码、实际ABI返回/释放、时钟/线程身份；原8项mock/边界测试保持。正式8块只运行一次，失败不补块。Python只在原生子进程外启动/保存，块内没有Python或模型。

本协议有独立的冻结source/executable SHA。先验证源码包，编译并通过测试，再冻结/核对实际exe；采集控制器和离线读取器复用，只有自己owned会话允许停止。所有日志/锁/ETL独占保留。不存在GPU、GUI、SDK、设备、人体或Run操作，也不改全局电源、调度或采样间隔。

初次构建被PATH里的零长度rustup符号链接拒绝，尚未生成测试/目标；只读核验后使用现存stable工具链的实际rustc.exe。原build01失败与build02成功结果保留，没有安装编译器或更改PATH/系统配置。

该门只验证已知退休指令工作与计数边界，不认证core/reference架构语义或GHz、真实负载扰动3%/1%、慢态根因或正式修复。

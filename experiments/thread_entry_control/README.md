# 线程入口字段：已知原生入口、系统查询与 ETW 的三方验证

单个生命周期合成窗口，两个不同的 DLL 导出函数分别作为实际 `CreateThread` 入口。两个线程先等待共同的释放信号，存活期间调用 `NtQueryInformationThread(ThreadQuerySetWin32StartAddress=9)`；随后释放并验证不同的实际退出码11/22。

## 交付结果

| 已知函数 | TID | DLL 内偏移 | 验证 |
|---|---:|---:|---|
| EntryA | 23160 | 0x1000 | 创建实参、系统查询、Start和End载荷均一致，实际退出码11 |
| EntryB | 15644 | 0x1030 | 创建实参、系统查询、Start和End载荷均一致，实际退出码22 |

DLL SHA256：`0e63700e79c2f211c56be9b3c462fd9d43559f496471ede70304ec78f81e014f`。ImageLoad记录的唯一目标模块范围包含两个地址，并且加载早于线程创建。两个不同地址和不同实际返回码也确认已知入口确实执行，不只比较两个getter。

在这两个线程实际交付的4个事件中，精确入口地址都唯一出现在载荷偏移48处。验证范围严格限定为 **Thread Start/End、version3、64位、74字节载荷**；其他版本、宽度、长度或重复匹配都拒绝，未宣称验证全部Windows线程模式。历史tracerpt模式错误记录保持原样。

PID所有权、TID、创建时间、存活查询时的STILL_ACTIVE、查询返回长度8、实际退出码、句柄关闭均记录。ETW实际Start/End包围存活查询的QPC区间。事件/缓冲区丢失为0，时钟落在原观测括号内，满足原1ms门槛。

## 安全结束与限制

仅启用ProcessThread/Loader，没有CPU样本、CSwitch/ReadyThread或StackWalk事件。WPR停止确认，外部查询未记录；采样间隔前后相同。全部线程退出，线程/事件句柄关闭，外部查询无相关进程，阶段锁和ETL保留在Windows。DLL与派生事件文件哈希独立核对。

六项测试覆盖已知地址、错误地址、不同版本、不同位宽、重复地址出现以及不同载荷长度，全部通过。

这个地址是**线程的启动入口**。它不代表当前栈、创建者调用链、GIL持有者、CPU热点或责任函数。通用CRT入口可能只映射到运行时模块，不能借此把该线程的全部工作归给CRT。这里用的是自编译oracle的已知导出身份，没有声称PDB解析通过。

最近固定模型窗口未录ETW，其3个新增TID仍不能追溯归属。此验证也不能使真实负载扰动、旧CPU栈闭合或3%/1%门槛通过。

## 下一步

现在可以为新冻结的固定原模型诊断同时记录生命周期、已持有线程计数和经过验证的入口字段；必须保留未解释CPU余额与未知/通用入口。对窗口后仍存活的新线程，可再用系统查询交叉核对，但不能把它们退出后的查询失败当作没有执行。

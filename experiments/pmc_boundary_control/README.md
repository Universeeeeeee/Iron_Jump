# 已知指令工作量的显式边界校准

承接218cef0，仅解决旧六段循环落在同一CSwitch区间的缺口。独立目录、独立冻结计划，旧窗口/失败/锁不变；不复采旧计划，不运行GUI、模型、设备、人体、USB或Run。

一个进程执行固定顺序：空白(1)、8M、32M、32M、8M、8M、32M、空白(1)次原生循环。72字节CODE与旧正控制完全相同，预期退休指令18*N+2；仅增加每块开始/结束之间的Sleep10ms边界，QPC/OS线程计数记录与空白完全同结构。每次真实返回必须16*N，RX内存最终释放。不改电源/优先级/亲和性或采样间隔。

在查看结果前冻结：每块必须有不同且覆盖标记的目标运行区间，全部CPU线程链连续、实际配置顺序及目标生命周期吻合、零报告丢失；各活跃块退休指令/预期均在[0.97,1.03]；空白上界不超过最小活跃预期的1%；各活跃块OS线程CPU与CSwitch运行量差不超过31.25ms（2个旧观察到的CPU记账台阶，不是精度认证）。直接保留外包络及开销，不减空白、不拟合、不放宽。失败就停，不补块。

复用先前owned WPR控制器、三项计数及已纠正的离线读取器；原控制器五项mock加三项边界测试先通过。采集只一次，记录会话和停止/间隔核对，清理不明保留故障/锁。读取器只对既有ETL操作。

即使已知工作量通过，也不证明core/reference的架构单位或GHz，更不证明真实负载扰动3%/1%或慢态触发原因。通过后才能考虑最小真实工作计数边界；当前不启动该阶段。

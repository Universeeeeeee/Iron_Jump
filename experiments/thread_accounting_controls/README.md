# 全进程线程计费合成控制：首窗失败，原样保留

冻结计划原定三个控制：两个持续存活的计算线程、计量前已退出的保留句柄线程、两次枚举之间创建并退出的短命线程。只运行了第一个窗口，触发停止规则；后两个未运行，不能宣称其运行时验收通过。

## 失败位置

冻结整组计量上限 10 ms；实测开始/结束两组为 **41.182 / 41.344 ms**，失败原因 `group_read_width`。没有修改阈值、重采或替换结果。

| 部分 | 开始组 ms | 结束组 ms |
|---|---:|---:|
| 已持有线程句柄计数读取包络 | 0.0774 | 0.1107 |
| 之后的系统枚举及结果组装 | 41.1046 | 41.2329 |
| 完整组 | 41.1820 | 41.3436 |

单次线程计数读取 0.0088–0.0394 ms。超过门槛的时间集中在读数之后的 `CreateToolhelp32Snapshot` / Thread32 枚举及包装段；目前没有把该段继续细分，因此不能宣称 41 ms 全部是某一个系统调用。

本窗进程 CPU 2093.75 ms，保留线程 CPU 合计 2046.875 ms，差 46.875 ms。该差不是合格的线程池归属估计：本身包含观察器工作和异步计费。原本定义的合成宽容差值检查不能覆盖或豁免整组读取门槛失败。

## 完成与未完成

- 本地和 Windows 六项纯逻辑测试通过：退出、前后枚举变化、创建时间变化、计数回退、整组过慢，以及稳定枚举不能证明全生命周期覆盖。
- Windows 实际固定首窗失败，后续控制未运行。完整源 SHA、计划、失败执行输出和结果保留。
- 创建的两个线程均已退出，持有句柄已确认关闭；结束后外部查询无 Python/observer 进程。远端原始结果 SHA 独立核对，原锁保留。
- 未运行真实模型、GUI、现场设备、人体或 ETW；正式程序未改。
- `whole_process_lifetime_coverage_proven` 始终为 false。当前仅凭前后枚举无法排除中间短命线程，不能出具完整进程归属。

## 下一设计边界

新的冻结版本应将昂贵的系统枚举移出工作计量区间，分别保存枚举自身时间；在门控工作开始前完成枚举并持有句柄，使用快速计数读组作为边界，工作完成后先取结束计数，再枚举和关闭句柄。整组计数读取仍使用原 10 ms 上限，单次仍为 1 ms。

这不是删除观察器成本：枚举的绝对时间、CPU 成本与所在阶段必须单独报告，其预热/系统状态影响仍需后续校准。前后枚举之间的线程生命周期缺口继续保留，短命线程反例必须实际运行；任何完整覆盖结论还需要更低层生命周期证据。本失败文件和计划不覆盖，修改后必须生成新计划。

本阶段没有找到积压根因，未达到真实负载扰动或全线程计费验收。

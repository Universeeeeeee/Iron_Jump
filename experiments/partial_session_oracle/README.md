# 既有停止窗口部分报告重算：四窗完整值全部一致

此前会话隔离已验证停止边界及原始档案，但部分报告只检查计数/哈希。本阶段补齐这些固定窗口的**完整报告与质量历史原实现重算**，只读既有文件，没有新采集、actor窗口、真人或设备测试。

## 输入与比较方法

运行前冻结4个既有actor窗口的16个report/state/raw/result文件SHA，正常完整窗口先作正控制。重算从原保存输入取得WalkingConfig、Source原布局/线序、stream与quality_flags；从既有raw文件取得实际原始值/接收时刻，从actor原result取得已声明的accepted_last_sample。**不使用被测部分报告中的指标或结果构造计算输入。** reason由原控制场景预先指定。

直接创建未修改的GaitEngine、DeviceQualitySession和原BeamQualityPolicy；调用原on_frame、arm_checked、质量halt、原滤波flush及原build_report。原NumPy二进制、过滤器和Processor不变。原checked样本仍是48903，不重编号，不压缩设备时间。

只重放截至原接受边界的帧；冻结之后已保存但未被接受的入口尾部不再作为测量输入。逻辑perf_counter_ns仅在本轮离线线程返回原记录的接收时刻，最后恢复；它不重建Qt调度、实际CPU交付或等待时长。

报告和完整quality/runtime/audit/timeline/mirror/rawarchive状态逐值精确比较，**没有删除字段或归一化主机时间**。连preflight checked_monotonic_ns也保持原值。比较器保留差异路径，首次不匹配即停止，不通过增加窗口、删除历史或修改边界凑通过。

## 仍保留的失败和限制

原停读队列的父验证器poll异常、旧JSON记录失败和writer停止未确认仍是原结论。`session_outbox_actor` 的原队列complete=false和writer_stop_confirmed=false都没有被本次重算改变。报告算法一致不表示传输成功、故障窗口成功或实际GUI延迟通过。

本轮不运行Qt事件循环，不模拟输入读取、IPC、模型或绘图负载；原输入的时刻只用于值和预检时钟一致性，不能将重算时间解释为现场性能。没有CPU/GIL比例或根因份额结论，旧完整栈与3%/1%资格失败保持。

## 验证与保全

本地与Windows4项比较测试通过，源码/输入/原oracle/原Python与NumPy二进制在运行前核验。准备时展开16个长路径的远端hash命令失败，随后用紧凑的目录/文件循环读取同16个哈希；当时未启动重算，更没有采集。`preparation_failure01.json` 保留该记录。

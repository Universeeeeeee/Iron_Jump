## 复核结果

四轮正式输入在USB组帧后的实际receipt速率均为999.991–1000.005fps，原wire/bits/validity、连续计数、raw archive、quality/runtime/audit/timeline、完整报告、录像CSV、最终空队列、reader和SDK关闭均由原独立`verify_trial.py`在Windows完整材料上通过。每轮11个active publication均实际paint；人体11步口述仍与算法lift/valid step分开，不用总数相近替代逐步正确性。

21:30与21:49按“入队≥990fps且pending≥1000或receipt-to-paint≥1000ms”的描述条件为严重真实积压；22:05和13:19不严重，但也均未达到旧250帧/250ms候选绝对目标。21:49接触窗平均消费约1002fps仍出现1.38s显示延迟，说明有限窗口平均追赶不能替代FIFO年龄和逐事件显示终点。21:30接触窗约886fps，表现为持续消费不足。

因此真实P1基线范围已经足够明确：上游可近1000fps持续入队，主机内积压可达秒级，且同一正式代码后续自然改善。不能把任一后续快态候选与较早慢态原版拼成A/B。

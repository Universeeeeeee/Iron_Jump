# 视觉模型进程隔离：固定原工作交付门通过，性能尚未验收

参考对话更新至对 `5ccccf1` 的审查，明确要求以GUI QoS为本轮诊断结束点，随后决定继续QoS、因基线不复现重设实验或转向消费者吞吐保障，暂停进一步通用性能工具开发。`dba6597` 已因严重默认基线不重复而无法判别QoS，`fda2ffd` 主动探针又未通过。这里结束这两条路线，按“原消费链隔离候选”推进一个独立实验：**只把视觉模型工作移动到子进程**。没有修改正式线程/进程结构、DirectConnection、滤波、Processor或绘图。

## 最小改变与真实交付

`workload_changes01.diff` 相对既有 `cpu_state_observation/workload.py` 只有一处实验适配器选择。原始消费链、6,824帧、共同7个进度点、220次真实推理、原图像与逻辑时间均不变。

本地模型组保留原 `_PreviewAdapter` 与模型线程；隔离组保留父进程调用线程作为IPC代理，模型由 `spawn` 创建的独立Python进程执行。11张准备图像在ready前一次性传递，逐图像字节哈希核对；工作区间只传 ordinal/slot/时间戳并返回原 `FootPoseSample`，没有重复传整幅图像、删推理、改变latest-only或压缩模型结果。此固定任务本来没有GUI或实时latest-only，不能冒充GUI行为验证。

固定两窗 `delivery_local` / `delivery_process` 均完成。独立复核确认：

- 完整原始报告、raw、质量、audit/timeline/mirror及全部220个真实模型返回，与既有原基准完全相同。
- 隔离组父PID3716、模型子PID20020/模型TID10956，确实不同进程；实际子推理区间包含于相应父RPC调用区间，并与原消费者区间重叠。
- 原像素、调用序列、逻辑时间、模型ready/最终close及父子退出均通过。子进程输出与退出确认后才宣布清理完成。

父进程 `model.thread_cpu_ns` 在隔离组是**代理线程CPU**，不是模型CPU；父进程CPU也不含子进程。子进程另存其PID/TID、真实调用边界与进程CPU/cycles，禁止将不同边界的计数直接求和或相减为等待/GIL占比。隔离本身同时改变GIL/地址空间及系统调度条件；未来若有收益，也不能唯一归因为某一种机制。

## 当前结果只通过交付门

两窗消费墙钟分别4849.616ms与4618.680ms。这是一对顺序执行的交付窗口，受状态漂移影响，**没有性能资格或稳定收益结论**。不能据此认定约4.8%的变化有效，也不将两个窗口追加到未来性能队列。

`next_performance01.json` 提出独立冻结的四对性能协议：原并发工作全部保持、交替顺序，要求四对均改善且消费几何平均至少下降20%，整组墙钟回退不超过5%；全部语义和实际子模型交付仍必须通过。这是与此前25.4%重叠损失量级相匹配的方向性门槛，不是旧3%/1%扰动标准，也不是GUI/1000Hz实时验收。性能队列尚未运行，需先完成该阶段的可执行计划与独立门禁。

最终仍须原GUI基线复现、队列年龄/峰值及contact→paint闭环，当前不能宣称根因或正式修复完成。若固定工作改善不足，就停止这个隔离候选，不反复补样或转成正式重构。

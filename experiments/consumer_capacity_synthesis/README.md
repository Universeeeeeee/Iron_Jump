# 严重窗口消费者容量下界

本分析只读取两个重启分离窗口的原 `queue_common` 和既有离线完整链结果，不启动目标。进程首窗在接触区间收到约1002帧/s、完成约797帧/s，队列约以205帧/s增长；要把同一区间限制在250帧，至少需约957帧/s，比实际提高约20%，等价于有效服务时间从约1.255ms/帧降到1.045ms/帧。原版第二窗约712帧/s，但其输入迟到较高，只作描述。

离线原完整链接触核心约0.55–0.576ms/帧，明显低于进程冷窗约1.255ms/帧。差额包含现场式GUI进程中的调度、GIL/Qt同步、会话封装和执行交付状态，不能相减后命名为任何函数。视频/MediaPipe已在子进程而消费者仍严重，排除它作为充分修复。

下一现有候选是将测量会话/消费者移到独立进程，因为它保留原滤波、Processor和报告链，同时移除GUI进程GIL/Qt竞争；其语义交付已通过，但严重态性能尚未合格。任何实现必须至少关闭本次测得的约160帧/s或0.21ms/帧缺口，且报告完全一致，才能进入现场验证。

同一boot追加的单个隔离消费者窗口表明，整个接触区间平均消费恢复到994.7fps，队列净增长仅约5.2帧/s；但前2.27秒只有846.8fps，队列从1升到346，随后2.50秒以1129fps清理到26。它把持续缺口缩小为早期瞬态，却仍未达到队列≤250和延迟≤250ms。剩余门槛约为早期阶段再提高5%或减少0.056ms/帧；下一步只定位这段成本，不把顺序窗口差异当因果比例。

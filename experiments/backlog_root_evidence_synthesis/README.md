# 数据积压根因证据矩阵

本目录只综合已经封存的 P0/P1 结果，不启动目标。当前最强结论是：消费者与 MediaPipe 原生执行共同出现的慢执行交付状态，是数秒积压的首要候选；真实 GIL 获取等待和 Qt latch 同时存在，但没有贡献比例或持有者证据。视频与模型进程隔离在四个快态配对中没有稳定明显收益，且严重状态在配对前自行消失，因此不能称为修复。

旧 PMC `service01` 的83.5967ms残差和31.25ms失败门保持，禁止从旧四窗计算CPU/GIL/缓存/频率份额。普通进程重启、5秒或合格5分钟低负载间隔也不是慢态的充分控制条件。

下一次有判别力的最小实验需要四次重启分离的首窗，顺序为进程/原版/原版/进程。该实验会中断 Windows 会话，因此只保存方案，待用户明确允许重启后执行。没有该条件前，不追加普通快态窗口。

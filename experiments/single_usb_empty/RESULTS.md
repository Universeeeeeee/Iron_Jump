# 单 USB 无人现场重复结果

**结论：当前保留的现场条件下，12/12 个正式阶段有效，未复现持续消费不足或持续队列增长；未启动 ETW/WPR，也未启动新的绘图 A/A 或 A/B。** 不能据此判断人体走跑性能正常，尚未证明原故障由哪一项 CPU/GIL/Qt 开销引起。

## 正式重复

## 实际相机与现场负载

相机原生帧计数约 99.96–100.03 fps，正式 GUI 实际预览约 21.07–21.33 fps，共绘制 7646 次。六组 SDK `tracking_start/stop` 均成功，无 SDK 错误，未产生非零速度控制。推理/SDK 决策主要为 `no_pose`，伴有启动 `loading` 和少量 `invalid_target`。关节点与 SDK 开关一直开启，但有效骨架仅最后一组预热阶段出现 16 次、132 个有效节点；其余 11 阶段有效绘制为 0。这些偶发有效连接不证明画面存在稳定人体，更不能代表持续全身骨架负载。

功能检查时的近距离模糊画面及光束 64 提示已告知现场；用户要求保留当前条件，未调整镜头/跑道/算法屏蔽。正式原始档案共 360152 帧，按原有预检坏点排除后，仅 21 帧还有 1 位活动光束，没有密集接触或有效算法脚印。正式质量事件列表均为空；功能检查中先前出现的运行期光束 64 提示保留在功能检查证据，未从原记录删除。

## 可成立的归因与剩余假设

1. **已验证的范围**：在本次单真实输入、当前近景、几乎无有效骨架、关闭录像的条件下，空场消费者可跟上约 1000 Hz 输入，未重复出现旧双输入实验的秒级持续欠账。此结论只覆盖有限时长和已存在的 P 探针条件。
2. **优先怀疑实验负载差异，不能指定单项根因**：旧实验同时有固定光束/图像回放、额外真实 USB、原生相机采集/录像及有效人体骨架；本轮使用正式渲染器及默认关闭的录像，画面和接触密度也不同。当前结果不能将差额全部归因于删除额外 USB、回放线程、录像、渲染器或场景中的某一项。
3. **仍未证实 CPU/GIL/Qt 的具体责任**：本轮只有应用层入队/完成和队列观测，没有 Running/Ready/Waiting、上下文切换或 GIL/GC 证据。总体输入进度接近 1000 Hz，也不能证明线缆到达始终均匀；USB 读取/组帧前的迟到仍需更低层证据。未满足正式复现条件，因此不启动原生调度记录校准。

**下一步最小验证**：待现场可调整时，将相机对准实际活动区域，在同一正式单 USB 拓扑、同样探针与参数下，先确认有持续真实人体骨架绘制，再安排实际接触密集走跑。记录真实接触密度和有效绘制量；若相同持续不足出现，再独立校准 ETW/WPR。当前没有证据支持立即优化某个算法/绘制层，也不建议移植 `beam_layer` 候选。

## 核验与交付

- 原始接触位均为二进制，设备毫秒计数逐帧连续；全部原有档案无截断、最终队列排空。完整报告、原质量快照与运行窗口状态、事件审计、镜像事件和时间线均保留。真实输入轮次不同，未声称跨轮报告字节相等或确定性 A/B 语义回归通过。
- 独立离线扫描核对 10861 条快照的进度、队列/批次不变量；Mac 与 Windows 分析最大数值差 `2.45e-15` 以内，分类完全一致。见 [verification.json](verification.json)、[results.json](results.json)、[results_windows.json](results_windows.json)。
- Mac/Windows 各核验 458 个正式基线文件无变化；探针与上一轮逐字节相同；上一轮 152 份证据哈希未变。见 [local_source_audit.json](local_source_audit.json)、[windows_source_audit.json](windows_source_audit.json)。
- [evidence_manifest.json](evidence_manifest.json) 列出 81 份原始输出/日志/功能截图的大小与 SHA-256。所有证据位于新的隔离目录，本轮未覆盖旧证据。原始现场文件 Git 忽略，Mac 和 Windows 各保留一份；相机本轮没有新增录像。
- 本轮只新增 `experiments/single_usb_empty/` 的实验脚本、冻结配置、清单与报告，未改正式程序、硬件/引擎/滤波/Processor 或 NumPy，未引入 Numba/C++/多进程。没有移植或合并绘图候选。
- 实验的 Windows 桌面任务已移除，实验 Python 进程无残留，SDK 关闭成功，USB 仍在系统中正常呈现；见 [windows_cleanup.json](windows_cleanup.json)。

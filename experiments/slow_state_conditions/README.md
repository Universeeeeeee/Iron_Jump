# 慢态条件：既有27窗的跨进程复发时间线

新目标是确认慢态产生条件，不继续优化绘图或扩大进程隔离。承接4702020。本阶段只读六份既有GUI归档及有界Windows历史日志，没有新GUI/计算负载、采样器、人体、USB、Run或设置干预，正式程序未修改。

## 现在可以确认什么

## “跑一轮就热好”不能作为现成解释

- 相同进程初始化每窗都会发生，但许多新进程直接快；纯进程内首次调用成本不足以解释整个慢窗。
- 最近A/B第一对原版及桥均慢，直到第三个新进程才快；“固定第一窗慢、第二窗必快”不成立。
- 先前快态之后出现新慢态，不能说此前某次运行永久预热完成。
- 新队列之间可见约69分钟、157分钟等观察空档后再慢；也有连续两个慢窗之间观察括号只间隔7.39秒。观察空档不是电脑空闲，也不是精确进程退出至启动时间，其中可能有其他实验、源分析或系统活动。不能据这些间隔拟合“空闲多久会慢”的阈值。
- 当前慢/快变化可以在模拟SDK条件下发生，真实SDK设备控制不是所有已保存慢态的必要条件；它仍可能影响某些实际现场轮次。不能由此否定设备状态对现场的其他影响。

## 历史系统条件核对

Windows本次报告LastBootUpTime为2026-10-15北京时间02:56:35，早于全部27窗。上述慢→快→慢过程没有要求重新启动Windows；该范围的保留GUI session/priority也相同。这不是当前硬件频率、热状态或电源交付测量。

read_history.ps1只查询本时间轴附近的Kernel-General（时钟/启动）、Kernel-Power（睡眠/唤醒/供电等）、Power-Troubleshooter、UserModePowerService、Kernel-Processor-Power及TerminalServices会话事件。日志开启且未触及501条上限，覆盖起始保留时间早于本时间轴；查询均返回空集，完整错误/元数据保留在windows_history01.json。没有开启日志或修改系统策略。

空集不证明未发生短暂频率/功率/温度/外部竞争变化，也不证明Windows自动策略未调整；部分事件类型不记录所有硬件变化。不能用它和相同policy getter组成“硬件稳定”的自证循环。

## 时间与测量层限制

688个manifest文件重新逐项SHA核验。每个窗口以本机QPC/perf轴排序，使用各端点自己的FILETIME包围转换成UTC/北京时间，不用模型日志字符串或提交时间当实验时间。

首次离线实现错误要求一个恒定UTC/perf偏移贯穿整窗，端点包围无共同交集而拒绝；该代码和失败保留在runs及clock_preparation_failure01。修订独立转换每个端点，显式保留UTC elapsed与perf elapsed差值（本组最大绝对界246500ns），不把UTC校时/缓调误认成CPU时长变化。没有重采原数据或放宽原窗口门槛。

三个测试覆盖端点独立时钟包围、缺失/倒置包围拒绝以及输入前缀身份的中途分叉不能由后来偶然相同覆盖。verification01记录全部归档/源码绑定、27窗身份条件与日志查询覆盖；不升级旧原生栈或3%/1%失败。

## 当前假设与下一项有判别力的验证

| 待检解释 | 已有约束 | 需要的证据 |
|---|---|---|
| 同进程首次执行/模型首次推理成本独自解释 | 慢差异持续到多次调用，多个新进程直接快，串行固定工作CPU账本也变 | 不能继续只增加ready等待或删首帧 |
| 跨进程缓存/工作集或空闲后状态重置 | 快后会慢，但观察空档没有完整空闲证据；7.39秒空档也有后继慢窗 | 明确控制同一工作进程之间的间隔，保持输入/线程/设置；同时记录非工作期间是否存在其他负载 |
| 系统执行交付/内存/原生忙等改变 | 模型open、消费CPU和原生模型执行均存在状态差异；标称PDH/策略getter无直接证明 | 同一慢/快窗口的执行交付、页故障/IO或调度证据；不能用cycles算GHz或wall减CPU算GIL等待 |
| GUI预览GIL或真实SDK是唯一条件 | 模拟SDK及无GUI固定串行工作也有慢态，预览桥未稳定消除严重症状 | 保留其已证实同步贡献边界，但不作为解释所有慢态的唯一机制 |

下一步先将“进程重新启动”和“运行间隔”拆开，用原始固定保存工作做预声明有限预算的条件控制；不使用已失败的主动CPU预热探针、不改变电源/线程/GC、不以反复运行凑慢态。必须在执行前固定短/长间隔顺序、状态判据和停止条件；若没有覆盖可辨别状态，仍为未知。本阶段没有启动该控制。

根因条件尚未确认。当前进展是把“首次运行”改写成可检验的跨进程复发状态，并排除了用Windows重启/重新登录作为这些保留复发的必需条件；缓存、空闲、CPU交付及内存路径仍待因果验证。无需真人测试，正式程序、历史失败、锁和冻结计划保持不变。

# 视频解码与 MediaPipe 进程边界：真实时序 A/A 与 A/B

本实验复用 `preview_gil_ab` 已验证的原 GUI、同进程 SessionController/QThread 消费者、1000Hz 保存 Walk 输入、真实原生 OBSBOT SDK、FIFO 与 contact-to-paint 观测。唯一变量是保存视频解码和原 `LiveWalkingVision`/`_PreviewAdapter` 位于 GUI 进程还是独立子进程。两组都使用原媒体时序、33ms 迟到跳帧、50ms latest-only 模型策略和原 GUI/SDK/Processor/报告链；实际视频帧和推理选择作为结果保留，不事后配平。

固定顺序先执行四个原版 A/A，再执行四对 AB/BA，共12个新进程。A/A 的接触至绘制、队列峰值、视频数和推理数相对范围均不得超过3%，否则定量归因直接判为不可用，但仍保留后续固定窗口的描述性结果。正式收益还要求至少3个原版配对窗达到队列下界≥1000帧且计划接触至绘制≥1000ms；进程组每窗队列上界和延迟均≤250，并在严重配对中至少降低50%。输入最大迟到必须≤100ms。

任何窗口基础设施、语义、真实 SDK、上下文或清理失败立即停止剩余队列，不重启、不补窗。旧3%/1%观察器校准失败、31.25ms CPU记账门和全部历史失败继续保留。本实验不修改正式程序、NumPy、滤波、Processor、绘图、电源、优先级或亲和性；保存输入结果不是现场修复。

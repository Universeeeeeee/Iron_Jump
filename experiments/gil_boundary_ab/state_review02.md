# 首两窗与后六窗的离线状态差异

这是查看 A/B 结果后的探索分析，不改变冻结主终点、不剔除窗口、不重采。原始归档逐文件哈希、队列守恒、有效接触逻辑、模型调用与 inference 的一对一时间链接均复核。分析脚本和结果分别为 `state_review02.py` / `state_result02.json`。

接触前窗口有 46–58 个完整模型调用；接触期有 228–229 个重叠调用。此处“接触期”指首末有效接触之间的连续包络，含步间空场；是按输入实际接收时间划分，而不是按消费者处理状态划分。

1. **模型调用变慢先于严重积压。** 首两窗在首次有效接触前就约 33 ms，后六窗约 19–21 ms。接触前队列很小。因此后续数千帧积压不是这项早期差异的充分解释。
2. **模型调用数量不足以解释差异。** 接触期调用数接近，但首两窗调用区间并集约 8.3 秒，后六窗约 4.7–4.9 秒。不同视频帧选择仍保留；未把数量接近当作等工作量，更未作事后匹配。
3. **初始化也发生在不同状态。** 首两窗模型初始化 6453/2914 ms，后六窗 1660–1697 ms。首窗初始化跨过 armed 时刻，另七窗在 armed 前完成。armed 本身不保证模型已热身；这个设计边界需要进入下一份冻结方案。
4. **主要积压仍位于绘制前。** 首两窗最大发布至绘制上界分别 181/200 ms，远小于各自 3.09/2.91 秒最大接触至绘制延迟。后六窗该上界为 60–85 ms。
5. **消费者的有效接触输入推进更慢。** 首末接触消费完成跨度的保守区间：首窗 20.675–20.860 秒，第二窗 19.467–19.526 秒；后六窗约 18.007–18.209 秒。完成边界由约每 64 样本记录的批次见证约束，不是逐帧精确计时。

## 可以与不可以得出的判断

下一步优先解释“为什么同样新进程回放中，模型调用在接触前已变慢，且消费者在接触期也变慢”。这比继续针对该 equality 边界做优化更有证据支持。

当前证据可排除“只有最终脚印绘制慢”的解释，也削弱“这一处 equality 替换即可稳定解决”的判断。它不能证明模型是竞争来源或唯一责任函数：模型适配器墙钟区间同时包含原生计算、GIL 获取、系统调度及其他等待。GUI `_read`/`_send_pose` 区间在慢窗也较长，但不是绘图计时，不能以其累计时间冒充 GIL 占用。

没有采集连续频率、电源/温度、系统其他进程负载或本批逐线程 CPU/cycles。不能将首两窗命名为冷启动、温升或节能模式，更不能把早期相关性升级为因果证明。模拟 SDK、共同观察器扰动未合格、动态视觉帧不同等限制继续有效。

## 下一份实验应回答的最小问题

保留这批作为发现证据。未来新方案应在任何分析前固定模型就绪边界，并同时保存原始启动窗口，不把未就绪/慢窗口删掉或替换。区分接触前和接触期的模型墙钟与 GUI/消费者线程 CPU/cycles；若墙钟增加而 CPU 不增加，继续查调度/同步；若 CPU 同增，再查具体计算与机器交付状态。CPU/cycles 也不能直接识别 GIL 持有者，仍需已校准的调用栈证据。

新增测量必须先通过独立合成校准及共同记录器扰动检验。不能把原有失败的 3%/1% 门槛改成通过，不因这份离线分析立即启动新 A/B 或人体采集。本阶段只读既有证据，无 Windows 运行、无正式程序改动。

验证：区间裁剪、嵌套并集合并、端点不相交与非法区间三项测试通过。八窗归档校验通过；全部结果保留。根因与正式修复仍未完成。

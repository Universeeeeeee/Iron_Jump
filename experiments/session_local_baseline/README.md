# 共同 GUI 的同进程原版接入通过，并复现严重积压

承接 `15e988c`。只执行冻结的一个保存 Walk 窗口，使用共同 `gui.run(plan, stage)` 绘制、视频/视觉、模拟硬件 SDK 路径。原版使用 `LocalSession` 将原 `SessionController` 保留在GUI、原Source/quality/消费保留在原QThread，直接转发原信号，**不增加测量IPC**。共同GUI同时留有既有隔离client的选择分支，但本计划只授权original；尚未运行共同GUI的配对隔离窗口。

这是必要的实验接入，不是正式Controller替换。只覆盖完整保存源prepare、SDK就绪、start、EOF排空、stop、报告与退出。Walk暂停、配置重试、真实设备取消、提前停止/故障部分数据边界等不由此新增资格。`client/actor`只是沿用独立报告/原始数据比较的目录格式；metadata明确标记original_same_process、无IPC和相同PID，不能把目录名作为进程隔离证据。

- 全部9个active publication ID（0、2、4、5、6、7、8、10、11）经过原脚印绘图。它们是发布ID，不是真人步数。
- 824视频提交、414次真实模型推理，有效骨架绘图和原SDK tracking start/stop、非零速度工作均获验证。动态选帧未事后配平。

本地和Windows6项测试通过。原启动身份错误、失败SDK回复不会释放源；start请求不会伪造运行状态。真实窗口另验证了线程归属和资源退出，而非仅凭mock或getter认定通过。

## 尚不能宣布隔离收益

上一隔离窗口的连续队列峰值界26～93帧、最大计划接触绘制193.484ms，本轮原版严重。但两轮不同时间、不同入口版本，**不能凑成因果A/B或计算改善百分比**。历史原版本有首轮严重、后续自然变快现象；本轮复现不能证明以后每轮都复现。

下一步可进入共同GUI的固定预算A/A和原版/测量子进程对照。需要冻结相同原始输入、媒体/renderer/模型/SDK政策，保留全部实际工作数、时间与角色；检查实际负载期间的上下文，而非只采启动状态或仅发生在接触前的ordinal1/100快照。比较目标是包含必要IPC的整体隔离方案，不能直接归因独占GIL。旧3%/1%扰动失败、严重原版至少3/4复现、每对改善、20%效应及候选250帧/250ms等既有门槛均不放宽，也不追加轮次凑基线。

目前仍无配对性能验收、扰动通过、根因函数或正式修复结论。不需要人体、USB、Run或优化正式程序；所有变化只在experiments。

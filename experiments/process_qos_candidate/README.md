## 对实际改善与测量范围分别解释

四对反向交替顺序下，消费者全部改善，是本次单一进程策略对固定工作有益的重复对照证据；不应因联合机制判据失败而抹去。事后阶段审查见 `stage_review01.json`：全部 28 个消费粗分段墙钟同向改善，消费 CPU 时间每对都下降。候选准备阶段仍为 **4682–4709ms**，没有回到历史约 2.8 秒快态。共同 ordinal 150–219 的 70 次模型尾部均在消费者结束后，默认中位数约 **32.42–32.66ms**，候选约 **30.40–30.67ms**。分段和调用不是新增独立试次。

原生探针是在模块导入、模型初始化、历史帧准备之前执行，结束到准备循环开始相隔 **8.80–9.14 秒**。它证明前置固定计算速度没有实质改变，**不能否定随后慢消费区间的 CPU 状态发生变化**。不将“原生未变”过度解释为整个运行期间频率或 CPU 交付都未变。当前也没有指令数、真实硬件频率、线程级 QoS 或完整等待份额来解释消费 CPU 的减少。

下一步应先核对实验进程与原 GUI 进程的执行策略和运行环境是否可比，并检验作用时间范围；不能再重复同一前置探针协议，也不能直接把 18.1% 移植为现场收益。若后续提出更接近目标区间的测量或 GUI 验证，须另立计划，保留本次联合失败。当前没有批准部署或正式代码变更。

2026-10-17 界面修复已部署：尾段提示不再累计，保存后可以正常退出。首轮 OFF 保留为故障样本；请重新从 OFF 开始，再 ON→ON→OFF。详情见 `UI_FIX.md`。

桌面文件夹：`IronJump-ETW-20261017`。新 Windows 实验根目录：`E:/OptoJump/IronJump-single-usb-human-etw-20261017`。初次部署没有自动开始现场采集，现场需手动打开上述入口。

## 现场直接操作

1. 接通光束设备与 Tiny SE，相机对准跑道，清空光栅。关闭其他占用设备的测试程序。
2. 建议先完成走路四轮：依次双击 **WALK-ETW-OFF → WALK-ETW-ON → WALK-ETW-ON → WALK-ETW-OFF**。这是关闭/开启跟踪的负载校准与重复复现，不是绘图优化 A/B。每轮均新进程、新目录，不自动打开下一轮。
3. 若 Windows 出现管理员授权提示，选择“是”；WPR 需要此权限。PowerShell 控制台会保留结束/失败信息，不要在采集中直接关闭控制台。
4. 新 GUI 顶部点击有边框的确认按钮，变成绿色“已确认”，先目视确认**全身及骨架持续可见**。相机原始录像、SDK 全身追踪与骨架绘制均自动开启；确认按钮不能替代真实画面核验。准备最多 5 分钟，超时自动取消并保留证据。
5. 点击“确认条件后开始”。程序先等待本轮 ETW 启动握手（OFF 入口同样等待但不启动 ETW），确认成功并重新检查全身/骨架就绪后才开始正式 5 秒空场倒计时。ETW 失败不会直接开始采集。
6. 等待提示音/屏幕“现在单次通过”，只走一次去程，从跑道外离开。由助手点击顶部“人已离开”，继续 15 秒空场，等待保存和关闭完成。不要在跑道内返回。若没有助手，原 60 秒正式采集上限会自动请求停止；不得将上限停止直接当作规范的人工离开标记。
7. 若骨架在通过期间消失，继续完成本轮，保留它作为负载不匹配证据；不要返回补步。顶部有实际有效骨架中断提示。缺少脚印也不要重走修补。
8. 控制台显示结束和证据目录后，按回车关闭，再启动下一入口。现场告诉助手每轮真实步数、首次迈入哪只脚、是否全程全身入镜和骨架持续可见。口述另存，不事后修改原报告或 starting_foot。

建议先分析走路四轮；是否需要跑步再按现场时间安排。如继续跑步，用 **RUN-ETW-OFF → RUN-ETW-ON → RUN-ETW-ON → RUN-ETW-OFF**，流程相同。只有部分轮次也全部保留，不能声称已完成完整人体负载校准。人体输入不同，OFF/ON 的数据密度、骨架量和 SDK 活动也须核对，不能机械相减当作严格等价。

取消时使用顶部“取消本轮并关闭设备会话”，或关闭实验 GUI 窗口；程序会请求停止并保存取消状态、关闭 SDK 和本轮 ETW。直接关 PowerShell、任务管理器终止进程或断电无法保证落盘。失败/取消轮次不会被标成有效性能样本，也不会覆盖或自动重跑。若显示已有实验锁/WPR 会话，不要强制清除：将控制台信息发给助手核验；程序不会取消别人的跟踪。

## 输出与边界

每轮位于 `experiments/single_usb_human_etw/runs/<时间_UUID_模式_开关>/`：

- `case.json`、本轮原子握手/正式起止标记、`controller_result.json` 和 WPR 启停日志。
- ON 轮的 `schedule.etl`：ProcessThread、Loader、CSwitch、ReadyThread；没有调用栈或 CPU 采样，也没有高频 Python profiler。
- `capture/`：原始相机 MJPEG+CSV（不是桌面录屏）、原始光束 wire/bits/有效位、设备/帧计数、完整事件/质量状态/报告、实际渲染与骨架计数、SDK 控制事件、队列深度/最老帧年龄/批次状态、GUI/消费者/USB reader 线程 ID、原生 CPU 与 FILETIME/perf 时钟括号。

原 NumPy、正式 hardware/engine/滤波/Processor/算法阈值、正式 renderer 和旧 beam_layer 候选均不修改。`field_runner.py`、QueueProbe P 是上一轮逐字节副本。新增观察只有正式起止两次线程 CPU 读数及低频握手/现有计数提示，人体负载开销尚待明早验证。ETW 在确认准备后、正式 arm 前启动，在 engine 停止排空后请求关闭，避免把几分钟调相机过程都录进 ETW。

`controller_result.valid_capture` 仅指采集和清理流程完成，**不表示负载匹配、吞吐正常、人体 A/A 通过或 ETL 事件有效**。新的密集窗、排空及负载门槛在启动前冻结于 `plan.json`。必须保留并核对原视频、实际骨架绘制量、原始数据/事件/质量/报告，再解释任何性能差异；计步正确性问题独立处理。

已保存的无人 6 对 OFF/ON 校准只覆盖空场、有效骨架绘制为零。本轮不把它外推为人体校准。CSwitch v5 解析及时间对齐仍须独立核验：tracerpt XML 曾显示与系统不一致的 +07:59，不可直接据此对齐。需以 FILETIME/perf 和 GetThreadTimes 跨源核验后，才解释 Running/Ready/Waiting；调度状态不能单独证明 GIL 或 GC。

## 程序检查

`test_protocol.py` 不启动 GUI、USB、SDK 或 WPR，检查握手身份、ETW 启动失败、超时后的归属、停止失败、外来会话保护、单实例锁、成功/失败清理。`check_ui.py` 是独立 Qt 界面与握手检查进程，明确拦截相机预览、USB 连接与 SDK 构造，不是真实设备联调。

`controller.py --check` 只验证管理员权限、458 个原正式源/冻结实验源/依赖哈希和 WPR profile，不采集设备数据。真实 USB/相机/SDK 联调及有人负载检验留待现场完成。

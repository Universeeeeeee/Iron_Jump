# 模式意图路由与异常光束容忍约定

2026-09-27 经 grill-me 对齐。本文是新增测试模式必须遵守的产品与数据契约；工程默认值不是精度保证。

## 模式意图先于参数生成

- 语音与打字使用同一入口。明确的自然语言需求决定模式，下拉框同步更新；不得先将需求强塞进当前模式的 Prompt。
- 支持纵跳、跑步机走路、跑步机跑步、地面走路、地面跑步。新增模式必须登记标识、显示名称、意图描述、配置模型/Prompt、设备约束和回归用例。
- 不明确地面/跑步机时先澄清：已识别单段询问两者，多段优先询问是否地面，段数未知不猜测。段数来自本次有效设备布局，不使用旧会话缓存。
- 明确需求与设备不兼容时说明原因，不替换成别的模式。参数仍需确认后才能应用。
- 准备阶段允许返回配置并切换，原建议、自检及开始确认失效；运行中必须先结束。迟到回复不能覆盖新选择。
- 模型仅决定受支持的业务模式与参数，不能更改自检阈值、故障清单或跳过开始确认。

## 自检与降级开始

- 五种模式都执行空场观察。默认连续观察 3 秒，使用设备采样时钟，完整性/连续性异常重新开始观察。
- 异常包含持续遮挡及反复闪烁。观察窗口内生成的是疑似故障清单，不声称已诊断硬件损坏；真实脚部和异物也可能导致相同信号。
- 自检按光束分别确认状态：连续相同候选至少 3 帧，且设备采样序号跨度至少 10ms；一束闪烁不能重置其他束。USB 到达时间不用于该判定，帧缺失或布局变化清空候选。当前还有待确认变化时不能开始。
- 只有确认后的状态达到持续遮挡或反复闪烁判据，才参与异常比例与连续束数统计。未达到确认时间即回落的短脉冲单独审计，不计入坏灯；确认过的短暂遮挡仍需等待稳定空场。地面准备页显示全程观察窗的异常段号、段内束号、类型、比例与阈值；光束详情的“本段当前帧无遮挡”不能代表全程自检通过。
- 未确认变化集合超过既有逐段比例或连续束数上限，记为一次大范围变化；连续维持只计一次，回落后再次出现另计。当前滚动观察窗内达到 3 次，标为“采集不稳定”并禁止开始，不能因过滤后画面平稳而放行。次数是初始工程判据，不是硬件故障诊断；随观察窗老化恢复，不能通过放宽段数平均值绕过。
- 每段分别计算异常光束数/实际光束数，默认上限 2.5%；不按固定段数计算全局平均。连续最多允许 2 束异常，跨段相邻位置一起检查；实际几何不连续处不能任意桥接。
- 健康、阈值内待确认、超限禁止开始三种状态明确区分。阈值内显示异常位置、类型、数量、比例，由操作者确认现场空场及接受降级后才允许开始。
- 设置页提供手动调整比例、连续束数、观察时长；参数修改使已有自检失效，运行中锁定。本次快照必须包含实际使用参数。
- 设备断流、丢失完整帧、无效数据不能伪装成正常无遮挡来通过自检。
- 因帧缺失或采集异常重启观察时，原因保留至完整观察窗口恢复；不能在下一帧只显示观察进度而隐藏反复重启的原因。

## 测试中的数据契约

- 开始时冻结故障清单。固定遮挡与闪烁点不参与触地/离地或空场结束判断，但原始采集值完整保留；界面与回放把不可用点和正常无遮挡区分。
- 不将不可用点补成真实接触，不跨大范围未知区推断脚。各模式必须分别处理触地、离地、边界、连通区域和不确定指标；缺少足够证据的事件/指标不得进入正常统计。
- 运动中不自动新增或取消屏蔽点。新的光束质量问题记录发生时间、位置及影响范围，不因其严重程度自动结束测试；正常完成条件与人工结束保留。
- 设备断开、持续无数据仍自动结束，报告保留已有数据和原因。设备布局/流变化不能无声拼接成同一段有效测量。
- 10ms 稳定确认仅用于开始前的诊断，不接入运行中原始帧、触地/离地计时或运行中质量观察。参考程序保持不变。
- 报告、历史和导出保留自检阈值、冻结清单、人工确认、运行中质量问题和统计限制。开始时另冻结 `preflight.stability`：确认时间/帧数、设备时钟、当时观察窗的短时变化束号与次数、大范围变化次数及上限。短时变化按“每束一次回落”计数，不是帧数，也不是整个准备阶段的累计次数；即使没有屏蔽点，界面和支持的 Report Agent 仍提示该记录。旧报告缺少字段表示未记录，不能解释为无异常。

## 新模式接入清单

1. 登记意图路由和配置/Prompt；验证明确切换、否定/比较语句、含糊追问、追问回答和迟到回复。
2. 接入统一自检与固定故障清单，不创建绕过确认的私有开始入口。
3. 明确模式的设备段数约束、未知光束对事件及指标的影响、恢复边界和正常结束规则。
4. 使用原始信号与质量快照生成可追溯报告，前端仅展示，不重新推算未记录的故障状态。
5. 回归覆盖健康信号、单/双异常束、三束连续、跨段接缝、每段比例、真实脚邻近坏点、低频闪烁、运行中新增异常、断流和布局变化；同时覆盖各束独立确认、USB 批量到达、短脉冲审计、大范围重复变化阻塞及原始运动短接触保留。离线回归不替代设备与视频真值验证。

## 验证边界

默认阈值需要真实设备验证。算法可以基于剩余有效证据输出结果，但不得宣称异常对精度没有影响。闪烁识别应与诊断窗口一致，不把一次毛刺或运动中的变化自动确认为永久坏点。

## 当前实现入口与验收方式

- `agent/config/intent.py`：结构化意图分类 Prompt 与确定性设备约束；`/config/chat` 的 `route_intent` 路径先选模式，再调用原模式配置 Agent。`AgentConfigPanel` 保存待澄清上下文，并用请求编号及模式版本防止迟到结果覆盖新选择。新增模式需要同步扩展意图结构、路由映射及原有模式配置注册表。
- `hardware/beam_quality.py` / `hardware/walking_preflight.py`：操作员策略、滚动完整帧窗口、逐束稳定确认、逐段比例和物理相邻连续束判断。当前疑似持续遮挡取确认状态的窗口占用 ≥95%；反复闪烁要求至少 4 次确认后的跳变。默认 1000Hz 下，10ms 跨度需要从首帧到第 11 帧持续一致，并不是收到 3 帧就确认。
- `engine/device_quality_session.py`：五种正式硬件模式共享的 Worker 线程质量门。`GaitEngine.process_quality_frame` 保留原始输入、向算法交付处理帧；邻近不可用点时保守中断事件配对，可能舍弃额外事件，不从未知点补造接触。
- 快照的 `bad_indices` 是物理顺序、从 0 开始的索引；界面显示的段号和段内束号从 1 开始。运行中质量事件时间以冻结自检样本为零点，不能直接当作地面首次落脚后的相对时间。
- 运行中持续遮挡与运动停留不能仅靠光栅完全区分，记录为疑似问题；高频变化目前以观察窗口内至少 20 次跳变记录。检测到的不确定区间不进入正常指标；这些工程判据仍需实际运动信号检验。
- `ui/quality_settings.py`：本机操作员设置独立持久化，模型配置无法写入。`beam_quality` 随报告保存，历史复用当次快照；Excel 设备质量表展开保存字段，避免单元格长文本截断事件。原始帧仍在既有有界导出缓存中，历史库不永久保存全速原始帧，长测试需注意缓存截断说明。
- `tests/test_mode_intent_routing.py`、`tests/test_beam_quality.py` 与原有 Agent/UI/地面算法回归覆盖本约定。在线分类使用模型替身验证协议；真人语音、云端模型理解准确率和坏点下测量误差必须另做实机验收。

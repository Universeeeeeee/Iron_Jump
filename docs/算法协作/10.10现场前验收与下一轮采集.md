# 10.10 现场前验收与下一轮采集

当前约束：单人、最多两脚；两脚可跨缝同时占三段以上光条，段数不是噪声判定条件。每段96束，固定1000 Hz；计时使用设备样本，不用视频时间或USB到达时间替代。本文是待现场执行的方案，不是现场通过记录。

## 已完成与退出10ms的门槛

走路候选闭合、首次未成熟碎片局部分组及未知位置的控制流保护已做离线反例和独立审查。分组仅延续光学跟踪，不能由一维轮廓证明一脚，未知触地/位置/左右及跨组关系保持未知。远处单束只有前置局部清场、单次单束观测、连续完整释放、无成长/重现/归属或质量缺口时才能作为非步排除；持续或宽岛不能按远近删除。

原始空间对照入口 `tools/compare_ground_frontends.py` 不连接硬件、不切换生产测量前端。它并列重放当前raw处理器和现有10ms路径，输出 `frames.jsonl`、双方summary和 `comparison.json`。逐帧raw/valid/wire、不可用束、接收时间、设备缺口和候选均可追溯；接触匹配只是光学时空重叠审查，不是真实脚ID。

本次NPZ没有运行期validity/quality flags，对照只能使用冻结layout和预检快照；工具明确写入此限制。原USB的CRC须由原包审计另验，不能将wire一致误当CRC验收。CPU分位数和filter递交延时只表示离线运行，不证明Windows相机/推理负载下没有积压。

走路保留10ms时，v1.9→v1.10现场完整summary逐字段不变；raw仍有14次issue、52条未决、0个支撑周期。原始路径尚不能取代10ms。取消条件是同源新现场的每脚首见/事件/确认边界、漏检重复、局部质量和支撑区间均有证据，并通过成熟融合、坏束、跨缝、缺口和尾部反例；不能按总数恰好12/10决定。

13与19口径已对齐：全局脚区清空统计临时忽略64诊断脉冲及576已知坏束，运动窗口58085–65844有13个单采样全清；逐脚完整包络有19个短清场区间、17个唯一起点。58870/60010各被两脚重复计数，60580/60700/60741是局部包络清空，65147是5ms。该诊断计数不改变任何原始位图，不作为64白名单。证据：`exports/ground_frontend_comparison_20261010/clear_scope_reconciliation.json`。

## 固定遮挡物的最小采集/主程序/最小采集 A/B/A

目的是区分上游载荷在运行条件下的差异。A=最小采集、B=主程序、A=最小采集；不是空场/运动/空场。保持电源、USB接口/线材、光条位置、同一DLL、设备段配置不变。健康段中间用不透光固定物遮挡约20cm，标记位置，稳定记录窗口内不移动；远离576坏束及模块接缝。每次只运行一个设备消费者。

用同一解释器在仓库根目录执行（现场既有解释器为 `D:\conda\python.exe`，执行前需重新核实）：

```powershell
D:\conda\python.exe -m tools.ground_capture_condition --condition minimal --label A1-fixed --output-dir exports/ground_condition_20261010/A1
D:\conda\python.exe -m tools.ground_capture_condition --condition main --label B-fixed --output-dir exports/ground_condition_20261010/B
D:\conda\python.exe -m tools.ground_capture_condition --condition minimal --label A2-fixed --output-dir exports/ground_condition_20261010/A2
```

最小采集自动记录60秒后停止；主程序正常操作，选软件手动结束，开始时先完成空场预检，固定物放到标记位置后保持60秒，最后手动结束并关闭程序，保证日志排空。先结束上个进程再运行下个条件。B的固定遮挡稳定窗口与预检/放置过程分开审计；固定物不满足人体测量契约，其报告不作为步态成绩。

脚本仅在当前进程加诊断回调，复用原有reader和启停函数，不改生产采集文件或算法。A/B都有同样原字节记录与SDK观察开销。记录包含：

- `condition.json`：解释器、源代码指纹、请求DLL绝对路径/指纹、DAYU/QT相关环境、排空及丢记录状态。
- recorder状态日志：timeout/chunk、capture_command_required、设备状态、启停reader、SDK StartCapture/StopCapture/显式write等请求和返回；已加载DLL另由Windows OS模块句柄查实际路径并校验文件指纹。
- pre-parser raw CSV：原始USB字节及接收时间；另做独立CRC/计数/逐束/脉冲和固定窗口审计。启动同步drain另记起止，其字节不在原包记录内，不能把录制窗口宣称为完整设备启动流。运行期质量快照包含实际frame/sample、valid bits、缺口及质量标志，须与layout预检快照分别核对。

SDK返回值不是USB OUT字节证据。DLL内部发出的命令字节不在该观察层；如果raw仍随条件变化，需要下一层USB trace或设备协议证据。先核对两条件DLL/参数/SDK调用序列，存在差异时不能直接归因相机。确认启动条件一致后，才在主程序内一次只改相机、推理或日志负载做追加对照。

脚本通过离线mock和manifest检查，实际Windows DLL、设备启停、摄像负载及60秒排空尚待现场验收。不能把这条命令已准备解释为实机通过。

## 正常走路/跑步的同源验证

新版本交叉回归后再统一部署，先核实Windows分支/提交及两个processor的实读SHA、报告算法快照。本轮部署的分支、提交与实读SHA另记于 `exports/ground_deployment_20261010`；历史Windows v1.6不是本轮版本。

使用main观察入口；同一轮保存pre-parser USB、导出XLSX、报告明细和含相机预览/概览的录屏。开启手动结束用于第一轮证据采集，保留出程前和末端离场后的空场，出程全走过设备末端，从跑道外返回。记录鞋型、方向、实际落脚次数与大致跨缝位置；不要为了某个算法总数调步数。报告保存完成再关闭程序，使raw日志排空。

首先各一次正常稍慢走路/跑步，随后按残留问题决定是否加单脚跨缝抬跟/落跟或单束短清场实验。单脚反例只验证分片归属，不能代替动态两脚身份验收。UI录屏可核实有没有漏计/重计及动作顺序，普通视频不能提供1ms力学触地真值。

收到数据后的验收按每脚执行：原包CRC/连续计数→USB/XLSX逐位同源→出程独立动作标签→候选归属/first_seen/事件/confirmed三个时间→每项指标所需边界与质量→末端及自动停止。重新启用自动结束另做同一轨迹对照，确认不会在未出程或pending期间提前结束。新的原始空间入口满足上述门槛后，才讨论让10ms退出正式测量、显示平滑继续保留。


## 本轮部署后的现场操作顺序

Windows仓库 `E:\OptoJump\Iron_Jump` 使用 `vae/iron_jump`。双击根目录 `start_ground_field_capture.bat`，依次选择1/2/3/4/5；每次自动创建带时间戳的独立目录 `exports\ground_field_20261010\<label>_<timestamp>`，不覆盖旧数据。不要同时开普通主程序、LED监视器或另一个采集窗口。固定物与出程实验都保持原10ms测量过滤，本轮正常步跑最小接触阈值设置为60ms，保持与既有现场记录一致（跑步配置类默认20ms，不是本轮对照参数），不在本轮现场改参数。

1. **A1固定物最小采集**：在健康第3段中部标记位置，用不透明固定物连续遮挡约20cm，避开接缝及已知坏束；人在跑道外，物体保持不动。启动bat选1，自动采60秒并结束；控制台显示进程退出和保存目录后再关。不要拔插设备或换USB口。
2. **B固定物主程序**：先移走物体以完成空场预检；启动bat选2，在界面选8m地面走路、软件手动开始/结束。开始后把同一物体放回标记处，稳定保持60秒，再手动结束。固定物报告不作为步态成绩。保存报告后关闭整个程序，等控制台确认退出；原包日志在本次B目录，放置前后与稳定窗口分开分析。
3. **A2固定物最小采集**：物体留在同一标记处、状态不变，bat选3，再采60秒。结束后移走物体。
4. **正常走路**：bat选4；界面选8m地面走路，软件手动开始/结束，最小接触时间60ms。完成空场预检，开始后保留约3秒空场，再以正常稍慢速度完整走过末端。沿跑道外返回，保留约3秒末端空场，然后手动结束。独立记实际触地次数，不把“有效步间”当总步数（12次触地最多11个相邻间隔）。
5. **正常跑步**：关闭上一程序并确认日志结束后，bat选5；界面选8m地面跑步，同样手动开始/结束、60ms，按照相同出程/空场/跑道外返回流程完成。

B及两次动态测试录屏都包含相机预览和报告概览，动态测试另复制报告明细TXT、导出Excel。Excel由程序存入 `E:\OptoJump\Iron_Jump\data`，文件名带时间；把对应xlsx/txt/mp4拷到此次label目录内。A1/A2不需报告或视频。每次关闭程序后等控制台结束再打包，目录应有condition.json、raw_*.csv及status_*.log；condition.json中recorder_drained应为true，丢记录与写入异常交由原包审核核验。

先上传上述5个目录，Mac可放到 `/Users/vae/Projects/Iron_Jump/现场测试/10.10`。如出现提前结束、预检失败或程序异常，也保留当轮原包、录屏和报告，不删掉失败轮。手动轮逐脚审核后，再用同一入口选择界面自动结束条件复测正常出程，专门验证终点/结束；不用第一次就混入自动结束机制。

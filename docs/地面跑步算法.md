# 地面跑步算法 v1

实现标识：`Overground Running Test`；界面名称：**地面跑步**。

地面模式独立于跑步机，不使用带速参数。设备段数由采集接口识别，不限制为 8 米。适用于单人、单向、区外助跑后进入、一次通过；分析光学步态，不输出标准距离冲刺计时，不测力或作医学诊断。

## 启动与采集

`OvergroundRunningConfig` → `GaitEngine.overground` → `OvergroundSession` → `OvergroundRunningProcessor`。

走路入口 `WalkingSession` 包装同一会话组件，仍使用原 `WalkingProcessor`，其中心参考计算、历史报告类型不变。底层 `WalkingPreflight` 名称保留以兼容已有接口。

1. 准备阶段开启采集，接收完整 `SensorFrame`，自动确认布局。
2. 连续 1000 个正常、空场样本通过自检；遮挡、校验失败、缺包、丢帧或布局变化会使准备失效。准备数据超过 500 ms 即过期。
3. 点击开始只请求布防。在处理帧的同一 Qt 线程重新核查准备状态，再把不可变 `PreparedDevice` 传入处理器。准备与测试不重启采集流。
4. 所有事件采用设备样本序号和 **1000 Hz**，不使用 USB 接收时间计算运动指标。首次有效接触达到最短时长后，起点回溯到该接触首帧。
5. 短暂丢帧、无效样本和协议错误分隔连续观测段；恢复后继续记录，不跨缺口拼接周期。断连、重启/计数回退、布局变化、连续 1 s 无数据中止测试。

配置快照保存算法版本、设备布局和光束坐标、采样率、身份及空间参考方法、以下工程默认值。实测校准状态为 `pending`。

| 参数 | 默认值 |
|---|---:|
| 接触确认 / 离地确认 | 3 / 3 ms |
| 最短有效接触 | 20 ms |
| 脚尖稳定平台 | 5 ms |
| 停步候选 | 2 s |
| 出口空场确认 | 500 ms |
| 准备过期 / 无数据中止 | 500 / 1000 ms |

接触候选和短事件不会从记录中删除后重新连接前后两步。确认窗口不平移事件时间；离地时间回溯到第一个未遮挡样本。短暂遮挡消失后重现保留不确定标记。

## 脚尖代理和距离

固定 **Tip-to-Tip**。官方手册允许脚尖和脚跟参考，本项目选择脚尖以保持与现有跑步机跑步默认参考一致，不宣称普遍更准确：[OptoJump 官方手册](https://training.microgate.it/sites/default/files/manuali/UserManual_OptojumpNext_EN.PDF)。

- 根据连续、身份关系可靠的落脚位置确认方向；方向未知时保留时间，空间指标留空。当前方向判定采用至少 0.15 m 的相邻落脚位移，属于待实测的追踪假设。
- 按实际光束坐标提取行进方向前缘，连续至少 5 ms、波动不超过局部一个光束间距构成候选平台；选择最靠前的平台中位数。
- 脚尖前缘被设备端点截断、接触合并、接触观测被中断或无稳定平台，则脚尖参考缺失。不补固定脚长，不回退到脚跟或中心。
- 步长为相邻异脚脚尖距离；跨步长为同脚两次脚尖距离。跨段几何直接使用 `layout.positions_m`，不使用全局编号乘固定间距。
- 步间时间为触地到触地；步间速度为步长/对应时间；平均速度为有效距离总和/这些距离对应的时间总和。

光学追踪仍有工程假设：相邻遮挡点物理间距不超过 0.04 m 归为同一簇；接触匹配允许 0.035 m 的位置余量；宽度超过 0.45 m、多于两簇或多重匹配按歧义处理。这些限制随算法版本记录，不能据软件测试宣称已适用于所有鞋型、拖脚或落脚姿势。

## 逐指标有效性

每项测量用 `{value, valid, missing_reason}` 表示。汇总只采用 `valid=true`，不把缺失填成零。部分无效时间记录可以保留原始数值用于审查，但不进入统计。

- 触地和离地是否完整观测分别记录；边缘进入不能假定真实触地时刻，边缘消失不能假定真实离地时刻。
- 接触后来发生丢帧，先前可靠的触地仍可用于对应步间时间；离地、完整接触时长及完整脚尖参考各自判为缺失。
- 同脚周期为 A→B→A 的触地到触地范围，分别给出周期、跨步长、接触、摆动、单支撑、双支撑及腾空。
- 单/双支撑与腾空由完整样本区间内遮挡簇数量积分，分别对应 1 / 2 / 0。周期终点之后的双支撑属于后续周期。
- 腾空需要完整连续的离地至下一触地证据；入口之前、出口之后及数据缺口不计腾空。完整观测且一直有接触可记为零；不足离地确认窗口的空白为不确定。
- 长接触达到 2 s 标为停步候选；不跨停步区间统计跑步步/周期，测量总时长保留这部分时间。
- 总时长为首个有效接触首帧至最后遮挡结束，排除开始后等候进入和出口空场确认。

## 身份、结束与报告

首脚可选择左、右或未指定。指定左右依赖“手动首脚＋单人交替步态”假设，逐接触保存来源；缺口、歧义、短事件使身份不可靠后，不继续沿用原左右锚点，只保留新的 A/B 关系。A/B 不代表经过独立识别的真实左右脚。

左右步长、接触时间分别要求每侧至少 3 个有效样本，计算：

`abs(左均值 - 右均值) / ((左均值 + 右均值) / 2) * 100%`

同时显示均值与样本数；不足时显示缺失原因，不自动诊断异常。

测试前选择自动或手动结束。自动结束需要方向确认、跟踪接触连续至少 3 ms 遮挡出口最末光束、随后持续空场 500 ms。证据不足继续等待并提示可手动结束；反向落脚达到方向阈值中止单向测试。边界证据不是一次标准距离冲刺计时。

报告包含接触、逐步、同脚周期、全部有效周期和有腾空周期的分组、无腾空/不确定数量、左右比较、停步和异常。无腾空周期保留，不自动归类为走路。完整设备宽度足迹回放、SQLite 历史恢复、Excel 导出均使用独立跑步报告类型。

Excel 含逐指标的值、有效性及原因、设备/配置快照和当前缓存的全部光束。原始帧沿用最多 600000 帧、按段数缩减至约 64 MiB 的缓存预算；截断时提示仅导出末尾保留帧。历史保存统计和足迹，不新增全速原始帧永久存档。

## 验证与实测边界

`tests/test_overground_running.py` 使用独立定义的 1000 Hz 合成遮挡轨迹；已覆盖 1/3/8/12 段、跨段、正反向、USB 批次、短接触、腾空/零腾空/不确定、双支撑、加速、停步、转身、无稳定脚尖、合并、丢帧恢复、身份丢失、自检失效、开始复核、冻结布局、中止、报告/历史和全宽导出。

软件事件真值与样本序号比较，误差目标不超过一个采样周期；空间真值与对应光束间距比较。软件测试通过不构成实机精度承诺。当前协议日志仅验证接口和回放链路，不作为已标注的跑步真值。仍需同步实机跑步日志、参考视频/事件标注、跨段与边缘案例，校准追踪阈值并评估实际测量误差。

## v1.1 连续性修正

逐步与同脚周期的腾空均核查每段空场之前实际最后离开的接触，不能仅凭相邻落脚记录的离地判断。边缘消失、离地未知时对应腾空无效，可靠步间时间仍保留。接触内不确定的短暂空白会撤销该接触及后续接触的左右锚点，后续可靠数据仍可按 A/B 统计。既有历史报告不重算，新报告快照标识 `overground_running_v1.1`。

## v1.2 按事件区间判断时间有效性

接触内第一次不确定空白记录发生样本。空白之前已达到最短有效接触及确认窗口的触地事件仍有效；在该空白之前已结束的步间时间、同脚周期时间及其可靠阶段统计不被追溯作废。跨越空白的步/周期、完整接触时间和脚尖参考仍无效，左右身份撤销规则保持不变。若空白发生在最短有效接触确认之前，不保留该候选的触地有效性。

正腾空独立依赖连续完整观测、实际最后离开的接触的可靠离地、下一次可靠触地。入口触地时间未知不再连带排除之后可靠的腾空；但对应触地到触地的步间时间仍缺失。零腾空仍要求完整周期区间证据，未知离地、短暂不确定空白及数据缺口不能变成有效腾空。新报告标识 `overground_running_v1.2`，历史报告不重算。

## v1.3 保留中断前的停步证据

连续性中断前已达到阈值的停步候选保留在最终报告，结束于最后可靠接触样本之后的一个采样周期；不跨缺口补齐，不因重复异常生成重复停步。不足阈值的中断前片段不与恢复片段拼接。新报告标识 `overground_running_v1.3`。

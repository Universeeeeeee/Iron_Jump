# 地面多米段走路：事件证据与验收

## 行为依据及范围

参考 [Microgate OptoGait User Manual v1.15.0](https://microgate-support-items.b-cdn.net/manuals/OptoGait_UserManual_EN.pdf)，起始脚说明见 §4.3.1.4.1–4.3.1.6，无效时间修正见 §5.3。官方允许人工指定起始脚、修正脚别及合并伪时间区间，但没有公开完整接触关联和确认算法。

本次修改 `WalkingProcessor`，用于单人直线、单次通过的地面多米段走路。地面跑步使用独立处理器，本次只做兼容回归。以下阈值、确认规则与提交顺序是 Iron_Jump 的工程约定，不宣称复刻 Microgate 内部算法，也不把跑步机 GaitR 直接作为地面走路配置。

## 接触与身份

- 所有米段先映射到全局光束坐标，再进行空间关联；接缝不重置接触身份。现有相邻遮挡分组与位置匹配规则保留。
- 保留包括单光束在内的候选区域。触地时间取首次候选遮挡，离地时间取首次缺失样本；确认延迟不改变这两个边沿。
- 有效接触需达到既有 8 cm 足迹宽度门槛、配置的最小接触时长和真实观测次数。宽度使用该接触已观测的最大值；确认等待不能增加真实观测次数。入口或出口边缘接触保留，但不参与完整接触指标。
- 候选按首次遮挡时间排列。较早候选未确认或拒绝之前，较晚接触即使已经确认，也不能发布脚别、更新行进方向或进入步/周期统计。报告将这种状态标为 `pending_touch_order`。
- 同帧首次出现的多个接触视为同时触地歧义；不同触地时间恰好在同帧确认不属于此情形。
- 操作员指定起始脚后，连续序列按 A/B 交替映射左右；未指定时只保留匿名 A/B。拒绝接触、缺帧、合并歧义后不自行恢复解剖侧别。A/B 仍是交替假设，不是对非交替动作的侧别识别。

## 短中断修正

只有采样连续、空间关联仍匹配且清空时长严格小于 `release_ms` 的中断可以合并。默认 10 ms：9 ms 合并，10 ms 和 11 ms 分成不同接触。过期判断发生在重新匹配之前。

每次合并记录 `merged_interruptions`：中断起始设备样本、恢复样本和原因 `release_debounce`，区间为左闭右开。设备固定 1000 Hz，因此样本数差即毫秒数。丢帧、无效样本等缺失证据不能作为去抖合并。

合并后的接触时长及基于它的支撑时长属于修正结果，包含记录的短中断；原始遮挡不能据此改写为连续观测。`observed_samples` 只统计实际遮挡观测。报告界面显示合并次数与毫秒数，Excel 以 JSON 保存完整中断记录，历史报告缺少这些字段时仍可显示。

## 周期与审计

继续使用同一身份段内三个相邻有效接触 A–B–A 建立周期，以两次 A 触地为边界；拒绝记录保留在序列中，禁止跨过它拼接周期。单、双支撑由接触区间重叠计算，不按米段拆分。现有保守规则要求三个接触均完整；本次未放宽终点接触尚未离地时的周期纳入条件。

接触报告新增触地确认时间 `confirmed_at`、离地确认时间 `lift_confirmed_at`、真实观测次数、最大宽度和中断合并记录。发生时间和确认时间均相对报告原点；中断记录使用设备样本编号。尚未确认或排序受阻的接触保留在报告中。算法版本为 `overground_walking_v1.3`。

## 验收

`tests/test_walking_event_evidence.py` 验证：

- 较早接触晚确认时，脚别、报告原点和方向仍遵循触地顺序；同时触地与同时确认分别处理。
- 单光束起止边沿、入口边缘残片、真实观测次数不受候选保留影响。
- 9/10/11 ms 清空边界、修正记录及缺帧不能合并。
- 未决候选阻止统计；候选拒绝后后续接触可以匿名提交。
- 3、8、12 米段、正反方向下，周期内单/双支撑时长与独立原始占用序列统计一致。
- 历史报告保存/读取保留修正证据与两类时间。

`tests/test_overground_walking.py` 覆盖跨米段接缝、断流、停止、设备接线、报告与 Excel 实际读回；`tests/test_overground_running.py` 和 `tests/test_ground_ui.py` 用于独立跑步模式及界面的回归。

这些检查验证算法行为与证据保存，不代表已验证实际触地精度。真实误差仍需同步视频或测力数据核对，尤其是拖步、前足着地、短步、双脚投影重叠及边界进入/退出。
